# Host 자신을 가리키는 IP 주소 — Loopback Address

## 개요

호스트(인터넷에 연결된 컴퓨터)가 **자기 자신을 가리킬 때** 사용하는 IP 주소를 **루프백(Loopback) 주소**라고 한다.
로컬 개발 환경에서 핵심적으로 사용되며, 실제 네트워크 트래픽이 외부로 나가지 않는다는 특징이 있다.

---

## 1. 루프백 주소란?

- **주소 범위**: `127.0.0.0/8` — 첫 옥텟이 `127`로 시작하면 전부 루프백
- **대표 주소**: `127.0.0.1`
- **문자열 별칭**: `localhost` → 내부적으로 `127.0.0.1`로 변환됨
- **가상 네트워크 인터페이스** — 물리적 NIC가 아닌 논리적 주소 (모든 호스트가 가지고 있음)

---

## 2. 왜 "루프백"인가?

일반적인 외부 통신과 달리, 데이터가 **IP 스택에서 되돌아온다.**

```
[외부 통신]
  소켓 → TCP → IP → NIC → LAN → 라우터 → 인터넷 → 목적지
                     ↑
              여기서 실제로 나감

[루프백 통신]
  소켓 → TCP → IP ─┐
                    │  목적지가 127.0.0.1이네?
                    │  밖으로 안 나가도 되겠다!
                    └→ 되돌아옴 (Loop Back)
  소켓 ← TCP ← IP ←┘
```

- IP 스택이 목적지 `127.0.0.1`을 보고 **NIC까지 내려가지 않고 되돌림**
- 실제 네트워크로 트래픽이 **전혀 나가지 않음**
- 그래서 이름이 **"루프(loop) + 백(back)"**

---

## 3. 로컬 개발 환경에서의 활용

바이브코딩 등 로컬 개발 시, 여러 서버를 한 PC에서 모두 기동하는 것이 일반적이다.

```
┌─────────────── 내 PC (localhost) ───────────────┐
│                                                  │
│  [Chrome]                                        │
│     │  http://localhost:3000                     │
│     ▼                                            │
│  [Next.js 프론트]  ←→  [Spring Boot 백엔드]      │
│    :3000                  :8080                  │
│                             │                    │
│                             ▼                    │
│                          [DB]                    │
│                          :3306                   │
│                                                  │
│  ※ 전부 127.0.0.1 위에서 포트 번호로 구분        │
└──────────────────────────────────────────────────┘
```

- 브라우저에서 `http://localhost:3000` 입력
- `localhost` → `127.0.0.1`로 변환 → TCP 3000번 포트로 접속
- 프론트 → 백엔드 → DB 간 통신도 모두 루프백으로 처리
- 원래는 서버 3대가 필요하지만, **한 PC에서 포트만 다르게** 하여 개발 가능

---

## 4. 루프백의 특성 — 사실상 IPC

루프백 통신은 네트워크 통신처럼 보이지만, 실질적으로는 **IPC(Inter-Process Communication)** 에 가깝다.

| 특성 | 루프백 (localhost) | 실제 네트워크 |
| --- | --- | --- |
| **트래픽 경로** | IP 스택에서 되돌아옴 | NIC → LAN → 라우터 → 인터넷 |
| **안정성** | 매우 높음 (메모리 카피 수준) | 패킷 손실·지연 발생 가능 |
| **에러 반응** | 즉시 발생 | 타임아웃 후 발생 (수 초~) |
| **속도** | 극히 빠름 | 네트워크 상태에 따라 가변 |

---

## 5. 주의사항 — 로컬과 실제 환경의 차이

### Java / Spring Boot 등 프레임워크 사용 시

- JVM과 프레임워크가 네이티브 수준의 복잡한 처리를 대신해줌
- 로컬에서 개발하고 AWS에 배포해도 **차이가 크지 않은 편**
- 바이브코딩 수준에서는 큰 걱정 불필요

### C / C++ 네이티브 코드 개발 시

> [!warning] 주의
> 루프백에서만 테스트하면 **실제 네트워크 배포 시 장애**가 발생할 가능성이 높다.

- 루프백은 너무 안정적이라 **네트워크 장애 상황을 재현할 수 없음**
- 연결 에러, 타임아웃, 패킷 손실 등이 루프백에서는 발생하지 않음

### 권장 테스트 구성

```
[노트북 (클라이언트)]            [데스크탑 PC (서버)]
   SKT 테더링 (LTE/5G)             KT 유선 (이더넷)
         │                              │
         └──── 서로 다른 네트워크 ───────┘
                    │
              실제 인터넷 경유
```

- 클라이언트와 서버를 **물리적으로 분리**
- 서로 **다른 네트워크**(예: 유선 vs 테더링)에 연결
- 이런 환경에서 이상 현상을 의도적으로 발생시켜 보면 완성도 높은 프로그램을 만들 수 있음

## 한 줄 요약

> 루프백 주소(`127.0.0.1`)는 호스트 자신을 가리키는 가상 IP로, 트래픽이 NIC까지 내려가지 않고 IP 스택에서 되돌아오며, 로컬 개발에 핵심적으로 사용되지만 **실제 네트워크와는 안정성에 큰 차이**가 있다.
