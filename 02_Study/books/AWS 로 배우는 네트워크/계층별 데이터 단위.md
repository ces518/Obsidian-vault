# 계층별 데이터 단위

## 개요

OSI 7 Layer 기준으로 **계층별 데이터 단위(PDU)** 를 정리한다.
Application의 Stream 데이터가 Segment → Packet → Frame으로 변환되는 과정과,
**MAC 주소는 구간마다 변하지만 IP 주소는 끝까지 유지**된다는 핵심 원리를 다룬다.

---

## 1. 계층별 데이터 단위 (PDU)

> [!important] 암기 필수
> 각 계층에서 다루는 데이터 단위(PDU)는 다르다.

| 계층 | 프로토콜 | 데이터 단위 (PDU) | 설명 |
|------|---------|-----------------|------|
| **L5~L7** (Application) | HTTP, SSL/TLS | **Stream** | 쭉 이어진 가변 길이 데이터 |
| **L4** (Transport) | TCP | **Segment** | Stream을 일정 크기로 자른 단위 |
| **L3** (Network) | IP | **Packet** | Segment에 IP 헤더를 붙인 단위 |
| **L2** (Data Link) | Ethernet | **Frame** | Packet에 ETH 헤더를 붙인 단위 |
| **L1** (Physical) | — | **Bit** | 전기 신호 (물리적 전송) |

### 프로토콜 참고

```
HTTPS = HTTP + SSL(TLS)

┌───────────────────────────────┐
│  L7: HTTP    ─ 웹 프로토콜     │  ← User Mode (크롬 등 Application)
│  L5: SSL/TLS ─ 암호화         │
├───────────────────────────────┤
│  L4: TCP     ─ 전송 제어       │  ← Kernel Mode (Socket 인터페이스)
│  L3: IP      ─ 라우팅          │
│  L2: Ethernet─ LAN 통신       │
└───────────────────────────────┘
```

## 2. Stream에서 Frame까지 — 단위 변환 과정

### 왜 잘라야 하는가?

- Socket의 본질 = **파일** → 파일 데이터는 일렬종대처럼 쭉 이어져 있음 (**가변 길이**)
- 인터넷에서 유통 가능한 최대 크기 = **MTU = 1,500 bytes** (매우 제한적)
- 예: 1.5MB 파일 → 약 **1,000개의 Packet**으로 분할해야 전송 가능

### 변환 흐름

```
Application (User Mode)
  │
  │  Stream 데이터 (가변 길이, 쭉 이어짐)
  │  예: 1MB 파일
  │
  ▼  ─── Socket ───
TCP (L4)
  │
  │  MSS (1,460 bytes) 단위로 댕겅댕겅 자름
  │  → Segment 생성
  │
  ▼
IP (L3)
  │
  │  IP 헤더(20 bytes) 붙임
  │  → Packet 생성 (최대 MTU = 1,500 bytes)
  │
  ▼
Ethernet (L2)
  │
  │  ETH 헤더(14 bytes) 붙임
  │  → Frame 생성 (최대 1,514 bytes)
  │
  ▼
  LAN 케이블 → 인터넷 → 목적지
```

### 택배 비유 복습

| 데이터 단위 | 택배 비유 | 설명 |
|------------|----------|------|
| **Stream** | 원본 선물 | 쭉 이어진 가변 길이 데이터 |
| **Segment** | 뽁뽁이 포장된 조각 | MSS(1,460) 단위로 자른 것 |
| **Packet** | 택배 박스 | Segment에 송장(IP 헤더)을 붙인 것 |
| **Frame** | 택배 트럭 | Packet을 실어 나르는 L2 단위 |

## 3. MAC 주소 vs IP 주소 — 구간별 동작 차이

> [!important] 핵심 차이
> - **IP 주소**: 출발지부터 목적지까지 **불변** (택배 송장의 보내는 사람·받는 사람)
> - **MAC 주소**: LAN 구간(Hop)마다 **계속 변경** (트럭을 갈아타는 것)

### 트럭 갈아타기 비유

```
철수 ──→ [LAN 1] ──→ [LAN 2] ──→ [LAN 3] ──→ 영희

Packet (IP 주소):
  Src: 철수 IP ─────────────────────────────→ 불변
  Dst: 영희 IP ─────────────────────────────→ 불변

Frame (MAC 주소):
  LAN 1: Src=철수NIC     Dst=GW1     ← 트럭 A
  LAN 2: Src=GW1         Dst=GW2     ← 트럭 B (갈아탐)
  LAN 3: Src=GW2         Dst=영희NIC  ← 트럭 C (갈아탐)
```

- 택배 박스(Packet) 안의 **송장(IP 주소)** 은 처음부터 끝까지 동일
- 택배를 실어 나르는 **트럭(Frame)** 은 구간마다 바뀜 → **MAC 주소도 바뀜**
- 최종 도착 시 Frame의 Source MAC = **영희 네트워크의 Gateway MAC**

> [!note] MAC 주소를 논하는 시점
> - **MAC 주소** → L2 구간(LAN)에 진입했을 때 논함
> - **IP 주소** → L3(인터넷) 수준에서 호스트를 식별할 때 논함

## 4. 전체 통신 흐름 — 철수 → 영희

### 송신 (Encapsulation)

```
철수 (User Mode Application)
  │
  │ ① 원본 데이터 (Stream) — 예: 1MB 파일
  │
  ▼ ── Socket (파일 I/O) ──
  │
  │ ② MSS(1,460) 단위로 Segment 분할 (약 700개)
  │
  │ ③ 각 Segment에 IP 헤더 → Packet (MTU=1,500)
  │
  │ ④ 각 Packet에 ETH 헤더 → Frame (1,514)
  │
  ▼
  LAN 케이블 → 인터넷 (Public Network)
               MAC 주소는 구간마다 변경
               IP 주소는 끝까지 유지
```

### 수신 (Decapsulation)

```
  영희 NIC에 Frame 도착
  │
  │ ① Frame → ETH 헤더 제거 → Packet 추출
  │
  │ ② Packet → IP 헤더 제거 → Segment 추출
  │
  │ ③ Segment를 순서대로 이어 붙이기
  │    (붙이고 → 또 날아오면 → 붙이고 → 이어 붙이고…)
  │
  ▼
  원본과 동일한 사본 완성 → 영희 Application에 전달
```

> [!tip] Decapsulation의 핵심
> 수신 측은 도착하는 Segment들을 **순서대로 이어 붙여서** 원본 Stream 데이터를 복원한다.

## 5. 식별자 정리 — 무엇으로 무엇을 식별하는가

| 식별 대상 | 식별자 | 계층 | 범위 |
|----------|--------|------|------|
| **NIC** (네트워크 인터페이스) | **MAC 주소** | L2 | LAN 구간 내 |
| **Host** (호스트/컴퓨터) | **IP 주소** | L3 | 인터넷 전체 |
| **Process** (프로세스/프로그램) | **Port 번호** | L4 | Host 내부 |

```
┌────────────────────────────────────────────┐
│  Host (IP 주소로 식별)                       │
│  ┌──────────────────────────────────────┐  │
│  │  Process (Port 번호로 식별)            │  │
│  │  예: 크롬 (HTTPS = HTTP + SSL)       │  │
│  └──────────────────────────────────────┘  │
│  ┌──────────┐                              │
│  │ NIC      │ ← MAC 주소로 식별 (L2 구간)   │
│  └──────────┘                              │
└────────────────────────────────────────────┘
```

## 핵심 요약

> [!summary]
> 1. **PDU (계층별 데이터 단위)**: Stream(L7) → Segment(L4) → Packet(L3) → Frame(L2) → Bit(L1)
> 2. Application의 **Stream 데이터**는 가변 길이 — 인터넷 유통을 위해 잘라야 함
> 3. **MSS(1,460)**로 Segment 분할 → IP 헤더 붙여 **Packet(MTU=1,500)** → ETH 헤더 붙여 **Frame(1,514)**
> 4. 택배 비유: Stream=원본 / Segment=뽁뽁이 / **Packet=택배 박스** / **Frame=트럭**
> 5. **IP 주소는 출발~도착까지 불변** / **MAC 주소는 LAN 구간(Hop)마다 변경** (트럭 갈아타기)
> 6. 수신 측은 Decapsulation 후 Segment를 **이어 붙여** 원본 데이터를 복원
> 7. 식별자: **MAC**(NIC, L2) / **IP**(Host, L3) / **Port**(Process, L4)
> 8. **HTTPS = HTTP + SSL** / Socket = 네트워크를 추상화한 파일 인터페이스
