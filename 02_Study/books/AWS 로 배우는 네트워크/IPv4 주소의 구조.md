## 개요

L3(네트워크 계층)의 핵심인 **IPv4 주소 체계**를 다룬다.
주소 구조(Network ID + Host ID), Subnet Mask, 클래스 체계의 한계와 CIDR,
Public/Private IP의 차이, 그리고 AWS 환경에서의 IP 활용까지 정리한다.

---

## 1. 대전제 — 인터넷 = Router + DNS

> [!important] 인터넷의 핵심 구성
> **인터넷 = Router의 집합체 + DNS**

| 구성 요소 | 역할 |
|----------|------|
| **Router** | 네트워크를 대표하는 Gateway, 라우팅 수행 |
| **DNS** (Domain Name Service) | IP 주소를 문자열(도메인)로 변환해 기억을 대신해주는 서비스 |
| **ISP** (Internet Service Provider) | Router를 대규모로 보유한 사업자 (KT, SK, LGU+) |

- 작은 LAN들이 Router로 연결되어 거대한 인터넷을 형성
- IP 주소는 외우기 어려움 → 도메인 이름(문자열)으로 대체 → DNS가 변환

> [!note] AWS 환경에서는
> - **L2는 논하지 않음** → L3(IP) 이상부터 다룸
> - IP 주소 + 도메인 이름이 핵심 설정 요소

## 2. IPv4 주소의 기본 구조

### 32비트 주소 체계

| 항목 | 내용 |
|------|------|
| **버전** | IPv4 (현재 주류, IPv6는 아직 보편화되지 않음) |
| **크기** | 32비트 (4바이트) |
| **총 주소 수** | 2^32 = 약 **43억 개** (이미 고갈) |
| **표기법** | Dotted Decimal — 8비트(1옥텟)씩 4개로 나눠 10진수 표기 |

```
  11000000 . 10101000 . 00000000 . 00001010
     192   .   168    .    0     .    10       ← Dotted Decimal
  ├──8bit──┤├──8bit──┤├──8bit──┤├──8bit──┤
                     32비트
```

- 각 옥텟의 범위: **0 ~ 255** (8비트 = 2^8 = 256가지)
- 주소 고갈 문제 → **NAT 기술**로 기존 IPv4 체계를 연장하여 사용 중

### Network ID + Host ID

> [!important] 핵심 구조
> **IP 주소 = Network ID + Host ID**

```
┌─────────────────────────────┬─────────────────────────────┐
│        Network ID           │          Host ID            │
│   (어느 네트워크인가?)        │   (그 안의 어느 호스트인가?)   │
└─────────────────────────────┴─────────────────────────────┘
```

- **Network ID** → 택배의 "서울시 OO구 OO동" (동네 식별)
- **Host ID** → 택배의 "몇 번지" (집 식별)
- 라우터는 **Network ID를 먼저 찾고** → 해당 네트워크 내에서 **Host를 찾는** 방식으로 작동

### Host ID의 제한

| Host ID 값 | 의미 | 할당 가능 |
|------------|------|----------|
| 모두 **0** | **Network Address** (네트워크 자체) | ❌ |
| 모두 **1** (255) | **Broadcast Address** (방송 주소) | ❌ |
| 그 외 | 일반 호스트 | ✅ |

## 3. Subnet Mask — Network ID 추출

> [!important] 정의
> **Subnet Mask** = IP 주소에서 Network ID와 Host ID를 구분하는 값
> IP 주소와 **비트 AND 연산**을 수행하여 Network ID를 추출한다.

### AND 연산 예시

```
  IP 주소:        192.168.0.10   → 11000000.10101000.00000000.00001010
  Subnet Mask:    255.255.255.0  → 11111111.11111111.11111111.00000000
  ─────────────────────────────────────────────────────────────────────
  AND 결과:       192.168.0.0    → 11000000.10101000.00000000.00000000
                  └─ Network ID ─┘
```

- Subnet Mask에서 **1인 비트** = Network ID 영역
- Subnet Mask에서 **0인 비트** = Host ID 영역 (AND 결과 무조건 0)
- `255.255.255.0` → 앞 24비트가 Network ID

### 확인 명령어

| OS | 명령어 | 확인 가능 정보 |
|----|--------|-------------|
| **Windows** | `ipconfig /all` | IP 주소, Subnet Mask, Gateway |
| **Linux** | `ip addr` | IP 주소, 서브넷 정보 |

## 4. 클래스(Classful) 체계 — 과거 방식

Network ID 비트 수에 따라 A/B/C 클래스로 고정 분류했던 **과거** 방식.

| 클래스 | Network ID | Host ID | 호스트 수 | 특징 |
|--------|-----------|---------|----------|------|
| **A** | 8비트 | 24비트 | 약 1,677만 | 소수의 거대 네트워크 |
| **B** | 16비트 | 16비트 | 약 65,534 | 중간 규모 |
| **C** | 24비트 | 8비트 | 254 | 다수의 소규모 네트워크 |

> [!caution] Classful 체계의 한계
> - Class A: 호스트 1,677만 개 → 대부분 사용 못함 = **IP 낭비**
> - Class C: 호스트 254개 → 중소규모 조직에게 **부족**
> - 클래스 단위로만 분할 → **유연성 부족**
> - **현재는 사용하지 않음** → CIDR로 대체

## 5. CIDR — 현재 표준

> [!important] CIDR (Classless Inter-Domain Routing)
> 클래스 개념을 없애고, **비트 수로 네트워크 범위를 자유롭게 지정**하는 방식
> **AWS의 모든 IP 설정은 CIDR 방식으로 표기한다.**

### 표기법

```
192.168.0.10 / 24
├───────────┤  ├┤
   IP 주소     Subnet Mask 비트 수 (왼쪽에서 24비트가 Network ID)
```

### CIDR 예시

| 표기 | Network ID | Host ID | 호스트 수 | 의미 |
|------|-----------|---------|----------|------|
| `/24` | 24비트 | 8비트 | 254개 | 소규모 네트워크 |
| `/16` | 16비트 | 16비트 | 65,534개 | 중규모 네트워크 |
| `/28` | 28비트 | 4비트 | 14개 | 아주 작은 네트워크 |
| `/32` | 32비트 | 0비트 | **1개** | 특정 IP 하나를 지칭 |

- `/32` = IP 주소 전체가 Network ID → **단일 호스트** 지칭
- CIDR 덕분에 네트워크 크기를 **필요한 만큼만** 자유롭게 지정 가능

## 6. IP 주소의 종류

### Public IP vs Private IP

| 구분 | Public IP | Private IP |
|------|----------|------------|
| **용도** | 인터넷에서 사용 | LAN 내부에서만 사용 |
| **유일성** | 인터넷 전체에서 **반드시 유일** | 같은 LAN 내에서만 유일 |
| **부여** | ISP가 할당 | 공유기(NAT)가 할당 |
| **외부 접근** | 가능 | 불가 (NAT 필요) |

### 사설 IP 대역

| 클래스 | 사설 IP 대역 | 대표 예시 |
|--------|-------------|----------|
| **A** | `10.0.0.0/8` | 10.x.x.x |
| **B** | `172.16.0.0/12` | 172.16.x.x ~ 172.31.x.x |
| **C** | `192.168.0.0/16` | **192.168.0.x** (가장 흔함) |

### 공유기와 NAT

```
┌─────────── LAN (Private IP) ──────────┐
│                                        │
│  PC: 192.168.0.10                      │
│  노트북: 192.168.0.11                   │
│  스마트폰: 192.168.0.12                 │
│         │                              │
│    ┌────▼─────┐                        │
│    │  공유기    │ Private: 192.168.0.1   │
│    │ (Gateway) │ Public:  ISP가 부여     │
│    └────┬─────┘                        │
└─────────┼──────────────────────────────┘
          │ NAT (주소 변환)
     ┌────▼────┐
     │ Internet │
     └─────────┘
```

- 공유기는 **Public IP + Private IP** 두 개를 모두 가짐
- 공유기 = 내부 엔드포인트의 **Gateway** (보통 끝자리 `.1`)
- 내부 → 외부 통신 시 **NAT**가 Private IP를 Public IP로 변환

### 특수 IP 주소

| 주소 | 의미 |
|------|------|
| **127.0.0.1** | Loopback — 나 자신을 가리키는 IP |
| **x.x.x.255** (Host ID 모두 1) | Broadcast IP — 해당 네트워크 전체에 방송 |
| **x.x.x.0** (Host ID 모두 0) | Network Address — 네트워크 자체를 지칭 |

> [!note] Broadcast IP와 MAC의 관계
> IP 레벨에서 Broadcast(Host ID 전부 1)가 되면, L2 레벨에서도 MAC이 `FF:FF:FF:FF:FF:FF`로 설정된다.

## 7. 캐스팅 방식 비교

| 방식 | 대상 | 설명 | 예시 |
|------|------|------|------|
| **Unicast** | 1:1 | 특정 호스트 하나에게만 전송 | 일반 통신 |
| **Broadcast** | 1:All | 네트워크 세그먼트 전체에 전송 | ARP 요청 |
| **Multicast** | 1:Group | 가입된 그룹에게만 전송 | **IPTV** (IGMP 프로토콜) |

> [!example] Multicast — IPTV 사례
> IPTV 송출 서버가 같은 채널을 보는 가입자 전체에게 **1회만 전송** → 가입된 수신자 전체에 동시 도달
> (Broadcast처럼 전체가 아닌, 가입된 그룹만 수신하므로 효율적)

## 8. AWS 환경에서의 IP

| 물리 환경 | AWS 환경 | 설명 |
|----------|---------|------|
| Public IP (ISP 부여) | **Elastic IP** | EC2에 할당하는 고정 Public IP |
| Private IP (공유기 내부) | **VPC 내부 Private IP** | EC2 기본 할당 IP |
| 공유기 (NAT) | **NAT Gateway** | VPC 내부 → 인터넷 통신 시 주소 변환 |
| LAN | **VPC + Subnet** | 사설 네트워크 환경 |

> [!tip] AWS VPC = 사설 네트워크
> - VPC는 기본적으로 **사설 네트워크 환경** (공유기 안쪽과 동일한 구조)
> - EC2는 Private IP만 가지므로 외부 접근 불가
> - 외부 접근이 필요하면 **Elastic IP**(고정 Public IP) 할당 필요
> - 모든 IP 설정은 **CIDR 표기법**으로 지정

## 핵심 요약

> [!summary]
> 1. **인터넷 = Router + DNS** / ISP = Router의 대규모 집합체
> 2. **IPv4** = 32비트 주소 (약 43억 개, 이미 고갈 → NAT로 연장 사용)
> 3. IP 주소 = **Network ID** + **Host ID** (택배: 동네 + 집 번호)
> 4. **Subnet Mask** = Network/Host ID를 구분하는 값 (AND 연산으로 추출)
> 5. **Classful 체계**(A/B/C)는 IP 낭비 → 현재는 **CIDR**(Classless)이 표준
> 6. CIDR 표기: `IP/비트수` (예: `192.168.0.0/24`) — **AWS의 모든 IP 설정에 사용**
> 7. **Public IP** = 인터넷용 (ISP 부여, 유일) / **Private IP** = LAN 내부용 (NAT 필요)
> 8. 공유기 = Gateway + NAT (Public ↔ Private 변환)
> 9. Unicast(1:1) / Broadcast(1:All) / **Multicast**(1:Group, IPTV)
> 10. AWS: **Elastic IP** = Public IP / **VPC** = 사설 네트워크 / 설정은 모두 **CIDR**
