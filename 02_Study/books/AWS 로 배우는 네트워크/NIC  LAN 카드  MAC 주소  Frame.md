# NIC LAN 카드 MAC 주소 Frame

## 출처

- AWS 로 배우는 네트워크 (책)

---

## 핵심 내용

OSI 7 Layer의 **L2(데이터 링크 계층)** 수준에서 알아야 할 핵심 개념들을 다룬다.
**NIC**, **MAC 주소**, **Frame**, **LAN**의 개념과 Ethernet 헤더 구조까지 정리한다.

---

### 1. OSI 7 Layer 학습 범위

| 계층 | 다루는 내용 | 비고 |
|------|-----------|------|
| **L1** (물리) | 케이블 규격, 전기 신호 등 | ❌ 다루지 않음 |
| **L2** (데이터 링크) | NIC, MAC 주소, Frame | ✅ 핵심 |
| **L3** (네트워크) | IP, 패킷 | ✅ 핵심 |
| **L4** (전송) | TCP/UDP, 세그먼트 | ✅ 핵심 |
| **L5** (세션) | 세션 관리 개념 | △ 간단히 언급 |
| **L7** (응용) | HTTP, HTTPS | ✅ 상세히 다룸 |

> [!note] HTTPS = HTTP over TLS
> - AWS 환경에서 웹 서비스 개발 시 **HTTPS 통신은 기본**
> - 현재는 SSL보다 **TLS**라는 용어를 사용
> - TLS는 OSI의 한 계층에 엄밀히 고정하기보다 여러 계층에 걸친 보안 프로토콜로 이해하는 편이 안전

> [!tip] 학습 순서
> OSI 7 Layer에서 **아랫집은 윗집의 존립 기반**이므로, L2 → L3 → L4 순서로 아래에서 위로 쌓아 올리며 공부한다.

---

### 2. NIC (Network Interface Card)

> [!important] 정의
> **NIC** = Network Interface Card (흔히 "랜카드"라 부르지만, **NIC**가 전문 용어)

### NIC의 두 종류

| 구분 | 규격 | 표준 기관 |
|------|------|----------|
| **유선** | Ethernet | IEEE |
| **무선** | IEEE 802.11 계열 (Wi-Fi) | IEEE |

- `802.11a/b/g/n/ac/ax/be`는 IEEE 802.11의 개별 amendment이며, Wi-Fi 세대와 대응됨
- **Wi-Fi 7** = IEEE 802.11be. 지원 기능과 실제 속도는 단말, AP, 채널 환경에 따라 달라짐
- **IEEE** = 전기전자 기술자 협회. `IEEE 802.11`은 무선 LAN 표준 계열

---

### 3. MAC 주소 (MAC Address)

> [!important] 정의
> **MAC 주소** = L2 링크에서 네트워크 인터페이스를 식별하는 주소
> 일반적인 Ethernet MAC 주소는 **48비트**이며, 제조사가 할당한 주소는 보통 전역적으로 고유하다.

### 같은 말, 다른 이름

| 용어 | 의미 |
|------|------|
| **MAC Address** | Media Access Control 주소 |
| **하드웨어 주소** | NIC에 제조사 할당 주소가 있는 경우의 별칭 |
| **물리 주소** | OS에서 MAC 주소를 가리킬 때 쓰는 별칭 |

> 일반적인 환경에서는 같은 뜻으로 쓰이지만, MAC 랜덤화나 가상 NIC 환경에서는 현재 사용 중인 MAC과 제조사 할당 MAC이 다를 수 있다.

### MAC 주소 구조 (48비트 = 6바이트)

```
  00 - 50 - 56 - C0 - 00 - 01
  ├──────────┤   ├──────────┤
   앞 3바이트      뒤 3바이트
   (OUI)          (고유 번호)
   = 제조사 정보    = 장치 개별 식별
```

- 16진수 한 자리 = **4비트**, 두 자리 = **8비트(1바이트)**
- 전역 관리 MAC 주소의 앞 3바이트(OUI)는 IEEE가 할당한 조직 정보를 나타낼 수 있음

### MAC 주소 변경 가능 여부

> [!warning] 현재 사용 MAC 주소는 변경 가능하다
> - 제조사가 할당한 기본 MAC(BIA)은 보통 NIC에 저장됨
> - 운영체제나 드라이버는 전송에 사용할 MAC 주소를 **소프트웨어적으로 덮어쓸 수 있음**
> - 가상 NIC나 로컬 관리 주소도 MAC 주소를 가질 수 있음

#### Wi-Fi MAC 랜덤화가 필요한 이유

무선 네트워크(Wi-Fi)에서는 MAC 주소로 기기를 추적할 수 있다.

→ 운영체제는 프라이버시 보호를 위해 네트워크별 또는 일정 기간별로 **로컬 관리 랜덤 MAC 주소**를 사용할 수 있다.

### MAC 주소 vs IP 주소

| 구분 | MAC 주소 | IP 주소 |
|------|---------|---------|
| **계층** | **L2** (데이터 링크) | **L3** (네트워크) |
| **크기** | 48비트 | 32비트 (IPv4) |
| **유일성** | 같은 L2 구간에서 충돌하지 않아야 함 | 라우팅되는 범위에서 충돌하지 않아야 함 |
| **용도** | 현재 L2 링크의 다음 장치 식별 | 네트워크 간 목적지 식별과 라우팅 |

> [!caution] MAC과 IP의 역할은 다르다
> IP 주소는 인터넷에서 목적지 네트워크를 찾는 데 사용하고, MAC 주소는 각 L2 링크에서 다음 장치에 Frame을 전달하는 데 사용한다.
> 라우터를 지날 때마다 Ethernet Frame과 MAC 주소는 바뀌지만, 일반적인 IP 통신에서는 목적지 IP 주소를 기준으로 라우팅한다.

### 4. LAN (Local Area Network)

> [!important] 정의
> **LAN** = 집, 사무실, 데이터센터처럼 제한된 공간에서 구성하는 로컬 네트워크

```
┌─────────────── LAN 구간 ───────────────┐
│                                         │
│  [PC]  [태블릿]  [스마트폰]              │
│    │      │         │                   │
│    └──────┼─────────┘                   │
│           │                             │
│      ┌────▼────┐                        │
│      │ 공유기   │ ← 경계 장치            │
│      └────┬────┘                        │
└───────────┼─────────────────────────────┘
            │
     ┌──────▼──────┐
     │   Internet   │  ← Public 구간 (ISP: SK, KT, U+)
     │  (L3 이상)   │
     └─────────────┘
```

> [!example] 가정 환경
> 가정용 공유기 안쪽 네트워크는 LAN의 대표적인 예다. 공유기의 라우터 기능은 보통 LAN과 인터넷의 경계 역할을 한다.

- LAN은 반드시 가정용 공유기 안쪽에만 존재하는 것은 아님
- 라우터는 서로 다른 IP 네트워크와 브로드캐스트 도메인을 구분하는 역할을 함

### 5. Ethernet II Frame 핵심 필드

L2에서 유통되는 데이터 단위 = **Frame**

> L2라는 말이 나오면 → **Frame** / Frame이라는 말이 나오면 → **L2**

> [!note] 단순화한 그림
> 아래는 Ethernet II Frame의 핵심 필드만 나타낸다. Preamble/SFD, FCS, VLAN 태그는 생략했다.

### 헤더 구성

```
┌──────────────────┬──────────────────┬────────┬─────────────┐
│ Destination MAC  │   Source MAC     │  Type  │   Data ...  │
│    (48bit)       │    (48bit)       │(16bit) │  (Payload)  │
└──────────────────┴──────────────────┴────────┴─────────────┘
     목적지 MAC          출발지 MAC      타입       데이터
```

| 필드 | 크기 | 설명 |
|------|------|------|
| **Destination MAC** | 48비트 (6바이트) | 목적지 MAC 주소 |
| **Source MAC** | 48비트 (6바이트) | 출발지 MAC 주소 |
| **EtherType** | 16비트 (2바이트) | 뒤따르는 데이터의 해석 방식 결정 |

> [!example] Type 값 예시
> `0x0800` → 뒤에 오는 데이터가 **IP 패킷**임을 의미

> [!note] Ethernet II와 IEEE 802.3
> Ethernet II에서는 이 16비트 필드를 EtherType으로 사용한다. IEEE 802.3 형식에서는 길이(Length)로 해석될 수 있어, 이 문서의 그림은 Ethernet II 기준이다.

| OS | 명령어 | 설명 |
|----|--------|------|

## 이해한 내용

> [!summary]
> 1. **NIC** = Network Interface Card (유선: Ethernet / 무선: IEEE 802.11 계열)
> 2. **MAC 주소** = L2 링크에서 인터페이스를 식별하는 주소이며, 일반적인 Ethernet MAC 주소는 48비트
> 3. 운영체제는 프라이버시 보호나 가상화 환경에서 현재 사용 MAC 주소를 변경하거나 랜덤화할 수 있음
> 4. 전역 관리 MAC 주소의 앞 3바이트(OUI)는 IEEE가 할당한 조직 정보를 나타낼 수 있음
> 5. **MAC은 L2, IP는 L3** — IP로 목적지 네트워크를 찾고, MAC으로 각 L2 링크의 다음 장치에 Frame을 전달
> 6. **LAN** = 제한된 공간에서 구성하는 로컬 네트워크이며, 가정용 공유기 안쪽은 대표적인 예
> 7. **Frame** = L2의 데이터 단위 (Ethernet II 핵심 필드: 목적지 MAC + 출발지 MAC + EtherType)

## 질문 / 헷갈리는 점

- 확인 필요: MAC 주소의 전역 고유성은 제조사 할당 주소에 주로 적용된다. 로컬 관리 주소, 가상 NIC, MAC 랜덤화 환경에서는 별도로 구분해야 한다.
- 확인 필요: TLS를 OSI L5로 고정하는 설명은 단순화다. OSI와 TCP/IP 모델의 계층 대응은 관점과 구현에 따라 다를 수 있다.
- 확인 필요: Ethernet II의 EtherType 필드와 IEEE 802.3의 Length 필드는 같은 16비트 위치를 다르게 해석한다.

## Knowledge로 승격할 후보

- `MAC 주소와 IP 주소의 역할 차이`: L2 링크 전달과 L3 라우팅의 역할 구분
- `Ethernet II Frame의 핵심 필드`: Destination MAC, Source MAC, EtherType의 의미
- `Wi-Fi MAC 랜덤화`: 로컬 관리 주소와 프라이버시 보호의 관계
