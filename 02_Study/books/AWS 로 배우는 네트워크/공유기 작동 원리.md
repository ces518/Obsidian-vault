## 개요

집집마다 있는 **공유기(Home Gateway)** 가 어떤 원리로 작동하는지 — 핵심은 **NAT(Network Address Translation)**.
- 공유기 = **L3/L4 Inline 장치** ([[Inline 구조와 라우터]] 와 동일 부류)
- **하나의 Public IP**를 여러 PC가 동시에 나눠 쓸 수 있게 해주는 기술
- 부산물: 외부에서의 직접 침입(웜 바이러스)을 막아주는 **방화벽 효과**
- 같은 원리가 AWS의 **NLB(Network Load Balancer)** 동작 이해의 기반
- 동작 방식에 따라 **Cone (Full/Restricted) / Symmetric** 으로 분류, 정밀도는 Symmetric 우위

---

## 1. NAT란? — Network Address Translation

> [!important] NAT (= NAPT)
> 정식 명칭은 **NAPT** (Network **Address + Port** Translation)
> 실제로는 IP만 바꾸는 게 아니라 **포트 번호까지 함께** 변환하기 때문.

### 기본 속성

| 항목 | 내용 |
|------|------|
| **풀네임** | Network Address (Port) Translation |
| **적용 계층** | L3 ~ L4 |
| **데이터 단위** | **Packet** |
| **장치 구조** | **Inline** ([[Inline 구조와 라우터]]) |
| **대표 장치** | 가정용 **공유기**, AWS **NAT Gateway**, NLB |

> [!tip] 분류 감각
> "NAT는 L3/L4 Packet을 다루는 Inline 장비." 이 한 줄만 기억하면 [[네트워크 장치 구조 Inline Out of Path Proxy|장치 구조 분류]] 안에 자연스럽게 들어간다.

## 2. 공유기 = 다재다능한 가정용 박스

> [!note] 공유기는 한 가지만 하지 않는다
> 가정에서 보면 공유기 하나가 여러 역할을 동시에 수행한다.

| 역할 | 설명 |
|------|------|
| **Gateway (NAT)** | 사설망 ↔ 인터넷 변환 (이번 주제) |
| **무선 AP** | Wi-Fi 신호 송출 |
| **L2 Switch** | 내부 PC 간 프레임 스위칭 ([[L2 스위치]]) |
| **DHCP 서버** | 내부 PC에 사설 IP 자동 할당 |

> 라우터는 아니지만 **라우터와 유사한 게이트웨이 역할**을 수행. 가정에서는 라우터로 통칭해도 무방.

## 3. Public IP vs Private IP — 공유기는 IP 2개

> [!important] 공유기는 IP 주소를 두 개 보유
> - **Public(Global) IP** — ISP가 할당한 외부용 단 한 개
> - **Private IP** — 내부 사설망에서 게이트웨이 역할용

### Private IP 대역 복습

| 클래스 | 대역 | 가정 사용 |
|--------|------|-----------|
| **A** | `10.0.0.0/8` | 기업/대규모 |
| **B** | `172.16.0.0/12` | 중규모 |
| **C** | `192.168.0.0/16` | **가정 공유기에서 가장 흔함** |

### 구조

```
                  [Internet]
                       │
                       │ Public IP: 3.3.3.3 (ISP 할당 1개)
                  ┌────┴────┐
                  │ 공유기   │
                  │ (NAT GW) │
                  │  Private IP: 192.168.0.1
                  └────┬────┘
                       │
        ┌──────────────┼──────────────┐
        │              │              │
   [철수 PC]      [영희 PC]      [길동 PC]
   192.168.0.10  192.168.0.12  192.168.0.30
   (모두 사설 IP)
```

## 4. 주소 변환 동작 — 출발지 변환과 응답 복원

> [!important] NAT의 핵심 동작
> 내부 → 외부 패킷의 **출발지 IP를 공유기의 Public IP로 바꿔치기**.
> 응답 패킷이 돌아올 때 **목적지를 원래 내부 PC IP로 복원**.

### Outbound (내부 → 외부)

```
[철수 PC 192.168.0.10] ──▶ [공유기] ──▶ [네이버 15.15.15.15]

패킷 헤더 (변환 전)              패킷 헤더 (변환 후)
─────────────────────           ─────────────────────
Src IP : 192.168.0.10           Src IP : 3.3.3.3    ← 공유기 Public IP로 변경!
Dst IP : 15.15.15.15            Dst IP : 15.15.15.15
```

### Inbound (외부 → 내부, 응답)

```
[네이버 15.15.15.15] ──▶ [공유기] ──▶ [철수 PC 192.168.0.10]

응답 헤더 (들어올 때)            응답 헤더 (내부 전달)
─────────────────────           ─────────────────────
Src IP : 15.15.15.15            Src IP : 15.15.15.15
Dst IP : 3.3.3.3                Dst IP : 192.168.0.10  ← 원래 PC로 복원!
```

### 네이버 입장의 착각

| 실제 | 네이버가 보는 것 |
|------|------------------|
| 철수가 자기 PC로 접속 | "3.3.3.3 이 접속했다" |
| 공유기는 접속한 적 없음 | "3.3.3.3 이 응답을 받는다" |

> [!tip] 공유기는 접속한 적이 없다
> Public IP는 공유기에 할당된 주소일 뿐, 실제 접속은 **그 주소를 빌려 쓴 내부 PC**가 한 것.

## 5. 부수 효과 — Inbound 차단 = 방화벽 효과

> [!important] NAT의 보안 부산물
> 의도한 건 아니지만, NAT 구조 때문에 **외부에서의 직접 침입이 차단**된다.

### 왜 차단되는가?

```
[외부 공격자] ──▶ [공유기 3.3.3.3 :포트?] ──X── [내부 PC]
                        │
                        ▼
                  매칭되는 세션 정보 없음
                  → 어느 내부 PC로 보낼지 모름
                  → Drop
```

- 외부 → 내부로 들어오는 패킷은 NAT 매핑 테이블에 **세션 정보**가 있어야 변환 가능
- 내부 PC가 먼저 나간 적 없는 트래픽은 매핑이 없으므로 **자동 Drop**
- 결과: **패킷 필터링 방화벽 유사 효과**

### 역사적 맥락 — 웜 바이러스 시대의 종말

| 시기 | 상황 |
|------|------|
| **1990년대 말** | 웜 바이러스 창궐, ISP가 공유기 = 불법 논란 (수익성 이슈) |
| **2000년대~** | ISP가 직접 공유기 배포, NAT 자동 보호 효과로 웜 침입 급감 |
| **현재** | "웜 바이러스" 용어 거의 안 쓰임 → "멀웨어" 로 통칭 |

> [!note] 이중 보호
> 엔드포인트(PC) 방화벽 + 공유기 NAT 두 겹의 보호로 외부 직접 침입 시나리오가 크게 줄었다.

## 6. 다중 사용자 공유의 문제 — DDoS 오인

> [!caution] 같은 Public IP가 N명을 가린다
> 외부 서비스 입장에서는 "한 IP가 N번 접속" 으로 보임 → DDoS 오인 가능.

### 시나리오

```
9시 출근시각, 한 사무실 100명이 동시 네이버 접속

[직원1 ~ 100] ──NAT──▶ 모두 3.3.3.3 으로 출현
                          │
                          ▼
                     네이버 측 방화벽:
                     "1초에 같은 IP로 100건? DDoS!"
                          │
                          ▼
                     ❌ 차단 위험
```

| 관리자 관점 | 주의사항 |
|-------------|----------|
| **IP 기반 Rate Limit** | NAT 뒤 다수 사용자가 함께 차단당할 수 있음 |
| **로깅** | Src IP만으로 사용자 식별 불가 → 추가 정보 필요 |

## 7. Port까지 변환하는 이유 — TCP 세션 식별

> [!important] IP만 바꾸면 응답을 누구에게 줘야 할지 모른다
> 철수도 길동도 모두 `3.3.3.3` 으로 변환되는데, 네이버에서 돌아온 응답은 누구의 것인가?
> → **포트 번호까지 조합**해서 세션을 구분.

### 매핑 테이블 예시

| 내부 IP:Port | → 외부 IP:Port | 목적지 |
|--------------|----------------|--------|
| 192.168.0.10:50001 | 3.3.3.3:**60001** | 15.15.15.15:443 (네이버) |
| 192.168.0.30:50001 | 3.3.3.3:**60002** | 15.15.15.15:443 (네이버) |
| 192.168.0.12:50001 | 3.3.3.3:**60003** | 16.16.16.16:443 (구글) |

- 응답이 `3.3.3.3:60002` 로 오면 → "길동(192.168.0.30) 것이군!"
- IP + Port 조합이 곧 **TCP 세션 식별자**

## 8. NAT 방식 분류 — Cone vs Symmetric

> [!important] 공유기는 둘 중 하나 — Cone 계열 / Symmetric 계열

### 분류 트리

```
NAT 방식
   │
   ├─ Cone 방식 (호스트 단위로 외부 포트 지정)
   │     ├─ Full Cone
   │     └─ Restricted Cone
   │
   └─ Symmetric 방식 (TCP 세션 단위로 외부 포트 지정)
                       └─ 더 정교, 보안성 ↑
```

### 비교

| 항목 | **Cone** | **Symmetric** |
|------|----------|---------------|
| **외부 포트 지정 단위** | 내부 **호스트** 단위 | **TCP 세션** 단위 |
| **세분화 정도** | 낮음 | **높음** |
| **외부에서의 예측 가능성** | 상대적 쉬움 | 어려움 (보안성 ↑) |
| **P2P 친화성** | ✅ 비교적 잘 됨 | ❌ 까다로움 (홀펀칭 어려움) |

> [!tip] 다음 학습: Symmetric NAT
> 보안성과 정교함 때문에 별도 깊이 학습 가치가 있는 방식.
> Symmetric NAT의 동작 원리를 이해하면 **패킷 필터링 방화벽의 보안 정책** 도 자연스럽게 이해된다.

## 9. NAT를 알면 함께 이해되는 것들

> [!important] NAT는 그저 공유기 기술이 아니다
> L3/L4 수준에서 일어나는 다른 기술들의 **공통 기반** 역할.

| 함께 이해되는 영역 | 연결 고리 |
|-------------------|-----------|
| **AWS NLB** (Network Load Balancer) | L3/L4 부하분산 = NAT의 응용 |
| **AWS NAT Gateway** | 동일 기술, Managed 형태 |
| **패킷 필터링 방화벽** | NAT 매핑 테이블 ≈ 방화벽 세션 테이블 |
| **포트 포워딩** | NAT의 정적 매핑 활용 |
| **STUN/TURN, P2P** | NAT 너머의 통신 기법 |

## 핵심 요약

| 기억할 것 | 내용 |
|-----------|------|
| **NAT 정식** | **NAPT** = Network Address **Port** Translation |
| **계층** | L3 ~ L4 (Packet, **Inline 장치**) |
| **공유기의 역할** | NAT Gateway + 무선 AP + L2 Switch + DHCP |
| **IP 보유** | Public 1개 + Private 1개 (총 2개) |
| **사설 IP 대역** | A `10./8`, B `172.16/12`, C **`192.168/16` (가정 흔함)** |
| **Outbound 변환** | Src IP를 공유기 Public IP로 변경 |
| **Inbound 복원** | Dst IP를 원래 내부 PC IP로 복원 |
| **부수 효과** | 외부 직접 침입 차단 = **방화벽 효과** |
| **다중 사용자 함정** | 같은 Public IP로 N건 → **DDoS 오인** 위험 |
| **Port 변환 이유** | 응답을 누구에게 줄지 식별 (IP+Port = 세션 ID) |
| **방식 분류** | **Cone (Full/Restricted) vs Symmetric** |
| **Symmetric의 강점** | TCP 세션 단위 변환 → 더 정교, 보안성 ↑ |
| **확장 이해** | AWS NLB / NAT Gateway / 패킷 필터링 방화벽의 기반 |
