# 인터넷 설정 자동화 — DHCP

## 개요

호스트가 인터넷을 사용하려면 **IP 주소·서브넷 마스크·게이트웨이·DNS** 네 가지 설정이 필요하다.
이를 수동으로 입력하는 대신 자동으로 받아오는 프로토콜이 **DHCP**이며, 특히 **브로드캐스트 기반으로 동작**하기 때문에 네트워크 세그먼트 범위와 보안 이슈를 함께 고려해야 한다.

---

## 1. 인터넷 사용을 위해 필요한 4가지 설정

| 설정 항목 | 의미 |
| --- | --- |
| **IP 주소** | 내 호스트가 사용할 주소 |
| **Subnet Mask** | 내 네트워크 범위 구분 (Windows는 CIDR 미지원, 직접 입력 필요) |
| **Gateway** | 외부(WAN)로 나가는 출구 라우터 주소 |
| **DNS Server** | 도메인 → IP 변환 서버 주소 |

> [!tip] DNS는 수동 설정이 유용할 수 있음
> 국내 통신사 DNS는 **접근 통제(사이트 차단)** 목적으로 활용되는 경우가 있어,
> **Google DNS (`8.8.8.8`, `8.8.4.4`)** 등 공용 DNS로 수동 설정하면 우회 가능.

---

## 2. DHCP란?

**Dynamic Host Configuration Protocol**
= 인터넷 설정을 **자동화**해 주는 프로토콜.

- PC가 부팅될 때 DHCP 서버로부터 IP·Subnet·Gateway·DNS 정보를 **한 번에 받아옴**
- 사용자가 직접 수동 입력할 필요 없음
- "자동으로 IP 주소 받기" 옵션이 곧 DHCP 활성화

---

## 3. DHCP 동작 원리 — 브로드캐스트 기반

### 핵심 의문

> "IP 주소가 없는 상태에서 어떻게 DHCP 서버와 통신하지?"

답: **브로드캐스트**를 사용한다. IP 주소 없이도 가능.

### 동작 흐름

```
[PC 부팅 - IP 없음]
     │
     │ "IP 주소 주세요!" (브로드캐스트)
     ▼
┌────────────────────────────────────┐
│  네트워크 세그먼트 전체에 전파     │
│                                    │
│  [옆 PC] → 응답 안 함 (서버 아님)  │
│  [옆 PC] → 응답 안 함              │
│  [DHCP 서버] → "이 주소 써!"       │
└────────────────────────────────────┘
     │
     ▼
[PC] IP·Subnet·Gateway·DNS 수령 → 인터넷 연결
```

### 전달되는 정보

DHCP 서버 응답에 포함되는 내용:

- 할당 IP 주소
- Subnet Mask
- Gateway 주소
- DNS 서버 주소
- (임대 기간 등 부가 정보)

---

## 4. DHCP 서버는 어디에 있는가?

### 가정 / 소규모 환경 — 공유기에 내장

```
[ISP (KT)] ──회선── [가정용 공유기] ──── [PC, 휴대폰, IoT]
                    ┌─────────────┐
                    │ Router      │
                    │ + DHCP 서버 │  ← 공유기에 모두 내장
                    │ + DNS 포워더│
                    └─────────────┘
```

- 대부분의 라우터/공유기에 DHCP 기능 내장
- DNS도 공유기가 캐싱·포워딩 역할 수행

### 기업 환경 — 별도 서버로 분리

PC가 수백~수천 대인 기업에서는 DHCP 서버를 **독립적으로 운영**하는 경우가 많다.

---

## 5. 브로드캐스트 도메인의 제한

> [!important]
> DHCP는 **브로드캐스트 도메인 내에서만 동작**한다.
> 인터넷 전역으로 전파되지 않는다.

- 라우터는 기본적으로 **브로드캐스트를 차단**
- DHCP 서버가 같은 L2 세그먼트 내에 있거나, **DHCP Relay**가 필요
- 브로드캐스트 전달 범위 설정이 DHCP 동작에 직접 영향

---

## 6. 기업 환경에서의 DHCP와 IP 관리

### 왜 별도 DHCP 서버를 쓰는가?

- PC 1,000대 규모에서 수동 설정은 현실적으로 불가능
- 부서별로 IP 대역을 나눠 관리해야 함 (마케팅 팀 / 개발 팀 등)
- 비개발자 부서원이 IP 설정을 직접 하기 어려움

### 발생 가능한 문제

| 문제 | 설명 |
| --- | --- |
| **IP 충돌** | 수동 설정자가 다른 PC와 같은 IP를 입력 → 둘 다 인터넷 안 됨 |
| **비인가 접속** | 외부인이 노트북을 회사 네트워크에 연결 → 인터넷 사용 가능 |
| **설정 오류** | 잘못된 대역 설정으로 통신 실패 |

### IP 관리 솔루션

- 국내에서 많이 쓰는 제품: **IPScan** 등
- 기능:
    - IP 충돌 감지 및 제어
    - 비인가 장비 차단
    - 대역별 권한 관리
    - DHCP 이력 추적

---

## 7. AWS 환경의 DHCP

- **EC2 인스턴스 생성** 시 IP 주소가 자동으로 할당됨
- 내부적으로 DHCP 메커니즘을 사용한다고 볼 수 있음
- 다만 **VPC 자체가 네트워크 구조를 정의**하므로, 사용자 관점에서는 DHCP를 신경 쓸 일이 거의 없음
- 네트워크 대역, 서브넷, 라우팅 모두 VPC 설정에 따라 자동 적용

---

## 한 줄 요약

> DHCP는 IP·Subnet·Gateway·DNS 설정을 **브로드캐스트 기반으로 자동 할당**하는 프로토콜이다. 가정/소규모는 공유기 내장으로 충분하지만, **기업 환경에서는 IP 충돌·비인가 접속 방지를 위해 별도 DHCP 서버와 IP 관리 솔루션을 함께 운영**한다.
