# 라우터에 대한 최소 이론

## 개요

라우터의 핵심 역할(게이트웨이, 경로 결정)과 라우팅 테이블의 원리를 다룬다.
특히 **라우팅 과정에서 IP 주소는 불변이지만 MAC 주소는 매 구간 변한다**는 점이 가장 중요한 포인트이다.

---

## 1. 라우터란?

- **인터넷 = 라우터들의 거대한 집합체** (+ DNS)
- 서로 다른 네트워크를 연결하는 장치
- LAN과 WAN의 **경계(게이트웨이)** 에 위치

```
┌─── Network A ───┐         ┌─── Network B ───┐
│  PC  PC  PC     │         │  PC  PC  PC     │
│       │         │         │       │         │
│   [L2 Switch]   │         │   [L2 Switch]   │
│       │         │         │       │         │
└───[ Router A ]──┘─────────└──[ Router B ]───┘
         ↑                          ↑
    게이트웨이                  게이트웨이
    (현관 역할)                 (현관 역할)
```

- 라우터 하나가 곧 **하나의 네트워크 세그먼트를 대표**
- 라우터를 벗어나는 순간 → WAN (외부 네트워크)

---

## 2. 라우팅 — 경로를 결정하는 행위

### 핵심 동작

1. 패킷이 라우터에 도착
2. 패킷의 **Destination IP** 확인
3. **라우팅 테이블** 조회
4. 적절한 **인터페이스(출구)** 선택
5. 해당 방향으로 패킷 전달

```
        인터페이스 C
             ↑
             │
패킷 →  [ Router ]  → 인터페이스 B
             │
             ↓
        인터페이스 A

"목적지 IP를 보고, 어느 인터페이스로 보낼지 결정"
= 라우팅
```

### 홉 (Hop)

- 라우터에서 라우터로 한 번 넘어가는 것 = **1 hop**
- 패킷은 hop을 반복하며 목적지에 도달
- 각 hop마다 TTL이 1씩 감소

---

## 3. 라우팅 테이블

라우팅의 **핵심 근거**. 목적지 IP를 보고 어느 인터페이스로 보낼지 규칙을 담고 있다.

### 예시 시나리오

```
[3.3.3.0/24]──[R1]──[R2]──[R3]──┬──[R4]──[6.6.6.0/24]
                                  │
                                  └──[R5]──[7.7.7.0/24]
```

**R3의 라우팅 테이블 (예시):**

| Destination | Interface | 설명 |
| --- | --- | --- |
| `7.7.7.0/24` | 아래 (→ R5) | 7.7.7 대역은 R5 방향 |
| `0.0.0.0/0` (default) | 위 (→ R4) | 나머지는 전부 R4 방향 |

### 정적 라우팅 vs 동적 라우팅

| 구분 | 설명 |
| --- | --- |
| **정적 (Static)** | 관리자가 직접 경로를 설정. 인터페이스가 하나뿐인 경우 등 |
| **동적 (Dynamic)** | 라우터끼리 정보를 교환하여 자동으로 경로 결정 |

### Default Route

- 라우팅 테이블에 **일치하는 규칙이 없을 때** 사용하는 기본 경로
- "모르겠으면 일단 이쪽으로 보내" → `0.0.0.0/0`

---

## 4. 루핑 문제

라우터들이 루프 형태로 연결되면, 패킷이 **무한히 순환**할 수 있다.

```
A → B → C → A → B → C → ... (무한 루프)
```

- 세 장비가 있는 힘껏 보내고 받다가 **전부 다운**
- **방지 방법**: 올바른 라우팅 설정, 루프 감지 메커니즘
- **TTL**: 만약 루핑이 발생해도 TTL이 0이 되면 패킷 폐기 → 최후의 안전장치

## 5. 핵심 — 라우팅 시 IP vs MAC 주소 변화

> [!danger] 절대 잊으면 안 되는 사실
> - **IP 주소 (L3)**: 출발지 → 목적지까지 **불변**
> - **MAC 주소 (L2)**: 라우터를 지날 때마다 **매번 변경**

### 왜 MAC 주소가 바뀌는가?

- IP 주소 = **최종 목적지** (택배 송장의 주소)
- MAC 주소 = **현재 구간의 배달원** (이번 트럭 → 다음 트럭)
- 라우터를 하나 건널 때마다 새로운 "트럭(프레임)"으로 갈아타기 때문

### 구간별 MAC 주소 변화 예시

```
[PC: 3.3.3.4] → [R1] → [R2] → [R3] → [R5] → [PC: 7.7.7.8]
```

| 구간 | Src MAC | Dst MAC | Src IP | Dst IP |
| --- | --- | --- | --- | --- |
| PC → R1 | PC의 MAC | **R1의 MAC** | 3.3.3.4 | 7.7.7.8 |
| R1 → R2 | R1의 MAC | **R2의 MAC** | 3.3.3.4 | 7.7.7.8 |
| R2 → R3 | R2의 MAC | **R3의 MAC** | 3.3.3.4 | 7.7.7.8 |
| R3 → R5 | R3의 MAC | **R5의 MAC** | 3.3.3.4 | 7.7.7.8 |
| R5 → PC | R5의 MAC | **PC의 MAC** | 3.3.3.4 | 7.7.7.8 |

→ **IP는 끝까지 동일**, MAC은 **매 hop마다 변경**

### Wireshark에서 확인되는 현상

- 같은 서브넷 내 PC가 보낸 패킷 → **해당 PC의 MAC**이 Source
- 인터넷에서 온 패킷 → 항상 **게이트웨이(라우터)의 MAC**이 Source
- IP 주소는 다양한 서버 주소가 보이지만, MAC은 항상 게이트웨이 하나

---

## 6. AWS 환경에서의 차이

| 환경 | L2 (MAC) | 라우팅 테이블 |
| --- | --- | --- |
| **온프레미스** | 직접 관리 필요, MAC 변화 이해 필수 | 네트워크 엔지니어가 설정 |
| **AWS VPC** | L2는 논하지 않음 (자동 처리) | **개발자/DevOps가 직접 설정** |

> [!note] AWS에서의 라우팅
> VPC 환경에서는 MAC 주소를 신경 쓸 필요 없지만, **라우팅 테이블 설정은 직접 해야 한다.**
> 클라우드 시대에는 개발자도 라우팅 개념을 알아야 한다.

---

## 한 줄 요약

> 라우터는 목적지 IP를 보고 라우팅 테이블에 따라 인터페이스를 선택하여 패킷을 전달하며, 이 과정에서 **IP 주소는 불변이지만 MAC 주소는 매 hop마다 바뀐다.**
