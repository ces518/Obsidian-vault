## 개요

L2 스위치의 **두 가지 종류**(Access / Distribution)와 각각의 역할, 관련 용어를 다룬다.
L2 스위치의 스위칭 판단 근거는 **MAC 주소**이다.

---

## 1. L2 스위치란?

> [!important] 핵심
> L2 스위치는 **목적지 MAC 주소**를 근거로 스위칭(경로 선택)하는 장치이다.

- 내부에 **MAC 주소 테이블**을 유지하며, 목적지 MAC이 어느 인터페이스(포트)에 연결되어 있는지 관리
- 자동으로 학습(Learning) → 리셋 시 재학습

---

## 2. L2 Access 스위치

> [!important] 정의
> **Access 스위치** = Endpoint(PC 등 단말기)와 **직접 연결**되는 스위치

### 특징

| 항목 | 내용 |
|------|------|
| **연결 대상** | PC, 노트북 등 Endpoint 직접 연결 |
| **별칭** | 스위치 허브(Switch Hub) |
| **판단 근거** | 목적지 MAC 주소 |
| **가격대** | 최저가 (~10만 원대) |
| **적용 범위** | 사무실 방 1개 정도 |
| **기능** | MAC 주소 기반 단순 기계적 스위칭 |

### 동작 원리

```
┌────────┐                        ┌────────┐
│ 노트북  │                        │   PC   │
│  (B)   │                        │  (A)   │
└───┬────┘                        └───┬────┘
    │ ①데이터 전송                     │
    │     ┌──────────────────┐        │
    └────▶│  L2 Access 스위치  │───────┘
          │  (스위치 허브)      │  ② 목적지 MAC 확인
          │  MAC 주소 테이블    │  → A가 연결된 포트로 전달
          └──────────────────┘
```

- 노트북(B) → PC(A)로 데이터 전송 시, **목적지 MAC 주소**를 확인
- MAC 주소 테이블에서 A가 연결된 **인터페이스(포트)** 를 찾아 해당 포트로만 전기 신호 전달

### 용어 정리

| 용어 | 의미 |
|------|------|
| **인터페이스** | LAN 케이블을 꽂는 단자(접점) |
| **포트(Port)** | 인터페이스의 다른 이름 |
| **24포트 허브** | 인터페이스가 24개인 스위치 허브 |

> [!tip] 공유기와 L2 스위치
> 공유기는 L2 스위치가 아니라 **L2 스위치 기능을 포함**하는 올인원 장치이다.
> - 라우터 기능 (일부)
> - L2 스위치 기능
> - 무선 AP(Access Point) 기능

## 3. 링크 관련 용어

| 용어 | 의미 | 비고 |
|------|------|------|
| **Link** | 장치 간 연결 회선 | 네트워크 다이어그램의 "선" |
| **Uplink** | 상위(더 넓은) 네트워크로 향하는 링크 | Access → Distribution 방향 |
| **Link-up** | 물리적 결선 정상 (녹색 불 점등) | Uplink와 무관 |
| **Link-down** | 물리적 결선 끊김 (케이블 분리) | Uplink와 무관 |

## 4. L2 Distribution 스위치

> [!important] 정의
> **Distribution 스위치** = **스위치를 위한 스위치** (Switch for Switch)
> 여러 Access 스위치를 하나로 묶는 역할

### 구조

```
                    ┌──────────┐
                    │  Router  │  ← 게이트웨이 (건물 단위)
                    │ (Gateway)│     인터넷으로 나가는 출입구
                    └────┬─────┘
                         │ Uplink
               ┌─────────▼──────────┐
               │   Distribution     │  ← 층 단위
               │     스위치          │     VLAN 기능 제공
               │  (100만 원대~)      │
               └──┬──────────────┬──┘
          Uplink  │              │  Uplink
        ┌─────────▼────┐  ┌─────▼─────────┐
        │ Access 스위치  │  │ Access 스위치   │  ← 방 단위
        │ (1번 방)      │  │ (2번 방)       │
        │ (~10만 원대)   │  │ (~10만 원대)    │
        └─┬───┬───┬─┘  └─┬───┬───┬──┘
          A   B   C       X   Y   Z
       [Endpoint]       [Endpoint]
```

### Access vs Distribution 비교

| 구분 | Access 스위치 | Distribution 스위치 |
|------|--------------|-------------------|
| **역할** | Endpoint와 직접 연결 | Access 스위치들을 묶음 |
| **적용 범위** | 방 1개 | 건물 1층 (여러 방) |
| **가격** | ~10만 원대 | ~100만 원대 이상 |
| **핵심 기능** | MAC 기반 단순 스위칭 | **VLAN**, 브로드캐스트 제어 |
| **특징** | 단순, 저가 | OS 탑재, Host처럼 부팅 |

### VLAN (Virtual LAN)

> [!note] VLAN = 논리적으로 LAN 묶음을 재설정하는 기능

- Access 스위치 하나를 기준으로 하나의 네트워크 Segment(구간)가 형성됨
- **브로드캐스트(Broadcast)** 는 네트워크 효율을 떨어뜨리는 원인
  - 브로드캐스트는 해당 Segment **내부로 제한**되어야 함
  - Distribution 스위치가 이를 중앙에서 통제
- VLAN을 사용하면 **물리적 위치와 관계없이** 논리적으로 LAN 구간을 재구성 가능

> [!example] VLAN 활용 예시
> 1번 방의 A가 2번 방으로 파견 → VLAN으로 A를 2번 방 Segment에 **논리적으로 편입** 가능

### 트래픽 흐름 예시

| 통신 경로 | 경유 | 설명 |
|----------|------|------|
| A ↔ B (같은 방) | Access 스위치만 | Uplink 불필요 |
| C ↔ X (다른 방) | Access → Distribution → Access | Uplink를 통해 Distribution 경유 |

## 5. 게이트웨이(Gateway) = 라우터

- Distribution 스위치 위에 **라우터**가 위치
- 라우터는 **게이트웨이** 역할 → 내부 네트워크에서 인터넷으로 나가는 **출입구**
- 비유: 건물 1층의 전체 출입구

| 단위 | 장치 |
|------|------|
| **방** | Access 스위치 |
| **층** | Distribution 스위치 |
| **건물** | 라우터 (Gateway) |

## 6. AWS 환경의 특수성 — SDN과 L2 추상화

### SDN (Software Defined Networking)

> [!important] SDN = 네트워크의 제어 로직을 소프트웨어로 재정의하는 기술

| 구분 | 기존 네트워크 장비 | SDN |
|------|------------------|-----|
| **성격** | **블랙박스** (Cisco 등이 정한 규칙, 변경 불가) | **화이트박스** (스위칭 논리를 자유롭게 재정의) |
| **Control Plane** | 장비 내부에 고정 | 소프트웨어로 분리·재정의 가능 |
| **Data Plane** | 장비 내부에 고정 | 실제 데이터 전달만 담당 |

```
┌───────────────────────────────────┐
│          Control Plane            │  ← 제어/판단 로직 (SW로 재정의 가능)
│  "어디로 보낼지 결정하는 두뇌"      │
├───────────────────────────────────┤
│           Data Plane              │  ← 실제 데이터 전달
│  "결정된 경로로 패킷을 운반"        │
└───────────────────────────────────┘
```

- AWS의 네트워크는 **SDN 기반**으로 구축되어 있다
- 따라서 물리적 L2 스위치 개념이 소프트웨어로 대체되며, 사용자에게는 **추상화된 인터페이스**만 노출

### AWS에서 L2가 없는 이유

| 물리 환경 | AWS 환경 |
|----------|---------|
| MAC 주소 기반 통신 | MAC 주소 기반 통신 **없음** |
| L2 스위치 직접 설정 | L2 설정 **불가 / 자동화** |
| Broadcast 발생 | Broadcast **없음** |
| VLAN 수동 구성 | VLAN 구성 **불필요** |
| STP 설정 필요 | STP 개념 **존재하지 않음** |
| ARP 브로드캐스트 | ARP **소프트웨어 처리** |

> [!caution] 핵심 차이
> 물리 환경에서는 L2가 네트워크의 기반이지만, AWS에서는 L2 계층이 **완전히 추상화**되어
> 사용자가 직접 다룰 수 없고, 다룰 필요도 없다.

### ENI (Elastic Network Interface)

- EC2 인스턴스에 붙이는 **가상 NIC**
- 각 ENI에는 **MAC 주소**, **Private IP**, **Security Group** 등이 할당됨
- 하나의 EC2에 **여러 ENI를 Attach** 가능 (물리 서버에 NIC 여러 개 꽂는 것과 유사)
- ENI를 다른 EC2로 **이동(Detach/Attach)** 가능 → IP·MAC 유지한 채 장애 대응

### 물리 vs AWS 구조 비교

```
물리 환경                          AWS 환경 (SDN)
┌──────────┐                     ┌──────────────────────┐
│ PC ─ NIC │                     │ EC2 ─ ENI            │
│    │     │                     │      │               │
│ L2 Switch│                     │  가상 네트워크 패브릭   │  ← L2 자동화
│    │     │                     │  (IP 기반 라우팅)      │
│  Router  │                     │  Route Table / IGW   │
└──────────┘                     └──────────────────────┘
```

### AWS 네트워크 핵심 정리

> [!tip] AWS 네트워크는 L3(IP)부터 시작한다
> - EC2에 MAC 주소가 논리적으로 존재하긴 하지만, **L2 스위치 연결 개념은 없음**
> - **가상 네트워크 패브릭**을 통해 IP 기반 라우팅으로 처리
> - **서브넷 + 보안 그룹** 설정만 잘하면 나머지는 자동으로 끝남

| 물리 환경 | AWS 대응 |
|----------|---------|
| NIC (랜카드) | **ENI** (Elastic Network Interface) |
| MAC 주소 | Virtual MAC (ENI에 자동 부여, 직접 사용 안 함) |
| L2 Access 스위치 | 존재하지 않음 (SDN이 대체) |
| VLAN | **VPC + Subnet** |
| Distribution 스위치 | 존재하지 않음 (SDN이 대체) |
| 라우터 / 게이트웨이 | **Route Table + IGW** |

> [!note] 그래도 L2를 알아야 하는 이유
> AWS가 L2를 숨겼을 뿐, 내부적으로는 동일한 원리(MAC, Frame, 스위칭)가 작동한다.
> L2의 원리를 알아야 **AWS 네트워크의 동작 원리를 근본적으로 이해**할 수 있다.

## 핵심 요약

> [!summary]
> 1. L2 스위치는 **목적지 MAC 주소**를 근거로 스위칭하며, **MAC 주소 테이블**로 관리
> 2. **Access 스위치** = Endpoint와 직접 연결 (방 단위, ~10만 원대, 스위치 허브)
> 3. **Distribution 스위치** = Access 스위치들을 묶는 스위치 (층 단위, ~100만 원대~)
> 4. Distribution 스위치의 핵심 기능: **VLAN** (논리적 LAN 재구성) + 브로드캐스트 제어
> 5. 인터페이스 = 포트 = 단자 (LAN 케이블 접점)
> 6. **Uplink** = 상위 네트워크로 향하는 링크 / **Link-up/down** = 물리적 연결 상태
> 7. **라우터** = 게이트웨이 (건물 단위, 인터넷으로의 출입구)
> 8. 공유기 = L2 스위치 + 라우터 + 무선 AP 기능을 포함한 올인원 장치
> 9. AWS는 **SDN 기반** — L2를 소프트웨어로 완전 추상화 (Broadcast 없음, VLAN/STP 불필요)
> 10. AWS 네트워크는 **L3(IP)부터 시작** — 서브넷 + 보안 그룹 설정이 핵심
