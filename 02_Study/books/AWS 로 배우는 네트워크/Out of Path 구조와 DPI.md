## 개요

네트워크 장치 세 가지 구조([[네트워크 장치 구조 Inline Out of Path Proxy]]) 중 두 번째인 **Out-of-Path 구조**와 함께, 패킷의 깊이 있는 검사 기법인 **DPI / SPI**를 다룬다.
- Out-of-Path = **트래픽 경로 밖**에서 패킷을 복사받아 **읽기만** 하는 센서 구조 (차단 불가).
- 핵심 기술 = **Mirroring** (Port Mirroring / TAP Switch).
- **DPI/SPI** = 패킷의 페이로드까지 들여다보는 검사 — 잘못하면 **도감청** 이슈로 직결.
- [[Inline 구조와 라우터]] 와 마찬가지로 **데이터 단위는 패킷(Packet)** 이다.

---

## 1. Out-of-Path = 경로 밖의 센서

> [!important] 본질
> "Path = 네트워크 경로". 그 **경로 밖(out)** 에 장치를 두고, 흘러가는 패킷을 **복사받아** 관찰만 한다.
> **센서 역할**을 하는 모든 장치는 본질적으로 Out-of-Path 구조다.

```
[Client] ──── 실제 트래픽 ────▶ [Server]
                  │
                  │ Mirroring (Copy)
                  ▼
            [Out-of-Path 센서]   ← 읽기만, 차단 권한 없음
```

### Inline과의 비교

| 구분 | Inline | Out-of-Path |
|------|--------|-------------|
| **위치** | 트래픽 경로 위 (반드시 통과) | 경로 밖 (복사 수신) |
| **데이터 단위** | **Packet** | **Packet** |
| **동작** | Read → Bypass / Drop | **Read only** |
| **차단 가능?** | ✅ | ❌ |
| **장치 다운 영향** | 트래픽 전체 차단 | 통신에는 영향 없음 |

> [!tip] 공통점
> Inline과 Out-of-Path 둘 다 **다루는 단위는 Packet**. 이 사실은 절대 잊지 말 것.

## 2. 어려운 일 — "무손실 수집"과 Line Rate

> [!danger] "센서니까 그냥 읽으면 되지" — 함정
> 네트워크 속도는 **SSD/HDD보다 압도적으로 빠르다.** 패킷을 빠짐없이 읽어내는 것 자체가 고난도 작업.

### 속도 비교 감각

| 매체 | 상대 속도 |
|------|-----------|
| 네트워크 (10Gbps~) | ★★★★★ |
| SSD | ★★★ |
| HDD | ★ |

### Line Rate (라인 레이트)

> [!important] Line Rate
> 회선의 **이론 최대 속도** 그대로 **무손실(0% drop)** 처리한다는 의미.
> "10Gbps Line Rate 지원" = 10Gbps가 쏟아져도 한 패킷도 흘리지 않음.

| 회선 속도 | 비고 |
|-----------|------|
| **1 Gbps** | 가정용 공유기 / 일반 PC 랜카드 |
| **10 Gbps** | 기업 / 데이터센터 |
| **40 Gbps 이상** | 가격이 기하급수적으로 폭등 |

> [!caution] "무손실 + Line Rate" 키워드 = 비싼 하드웨어
> 자동차에 비유하면 100km/h → 250km/h → 300km/h 가는 차 가격이 단순 2배가 아닌 것과 같다.
> Line Rate 무손실 수집을 위해서는 **수천만 원짜리 전용 하드웨어**가 필요하다.

## 3. Port Mirroring — L2 스위치의 복사 기능

> [!important] Mirroring = 원본과 100% 동일한 사본 보장
> 그냥 "Copy"인데, 원본과 사본의 **완전한 동일성**을 보장할 때 비로소 Mirroring이라 부른다.

### 동작 구조

```
┌──────────── L2 Switch ────────────┐
│                                     │
│  [Port1]  [Port2]  [Port3] ... [PortN]
│    │        │        │           │
│   Server    PC      Router    ← 미러링 포트 지정
│                                  │
│                          ┌───────┘
│   (Port1↔Port2 트래픽)    │ 모든 트래픽 Copy
│           ▼              ▼
│        실제 전달    [분석 PC / NIDS]
└─────────────────────────────────────┘
```

### 부담과 트레이드오프

| 항목 | 내용 |
|------|------|
| **CPU/NPU 부담** | 트래픽 한 건마다 복사 작업 추가 → 스위치 발열 ↑ |
| **잘못된 미러링** | 스위치 자체가 **다운**될 수 있음 |
| **장비 가격** | Port Mirroring 지원 여부에 따라 스위치 가격 차이 |
| **지원 범위** | Distribution Switch 급은 대부분 지원, Access Switch는 가끔만 |

> [!note] Timestamp 정밀도까지 스펙
> 미러링 시 타임스탬프를 **도착 시점** 기준으로 찍을지, **복사 완료 시점** 기준으로 찍을지도 스펙에 포함된다.
> 그만큼 예민하고 정밀한 기능.

## 4. TAP Switch — 미러링 전문 장비

> [!important] TAP = Test Access Point
> 미러링만을 위해 태생적으로 설계된 전용 스위치. 일반 스위치보다 훨씬 비싸지만, 부담 없이 미러링이 가능.

### Tapping Point — TAP 스위치가 놓이는 지점

```
[외부망] ───┐                ┌─── [내부망 / Web Server]
            │                │
       ┌────▼────────────────▼────┐
       │       TAP Switch          │  ← Tapping Point
       │      (미러링 전문)         │
       └───┬───┬───┬───┬───┬───┬───┘
           │   │   │   │   │   │
          NIDS │  서비스│ 포렌식 │ ...
           (보안)│ 모니터링│  (SSD저장) │
                │        │        │
                └─ 한 번 들어온 트래픽을
                   N개 포트에 동시 복사 ─┘
```

### TAP 스위치의 특징

| 항목 | 내용 |
|------|------|
| **태생** | 복사 전문 (Mirroring-only) |
| **포트 수** | 다수 (예: 10개에 동시 복사 가능) |
| **가격** | **고가** — 일반 스위치 아님 |
| **배치** | 설계 단계부터 미리 Tapping Point 확보 |

### Tapping Point 활용 예시

| 용도 | 연결 장치 |
|------|-----------|
| **해킹 탐지** | **NIDS** (보안 센서) |
| **서비스 안정성 모니터링** | 모니터링 서버 |
| **장애 분석** | 패킷 분석기 (Wireshark 등) |
| **포렌식** | SSD에 트래픽 통째로 저장 |

> [!tip] 미리 설치가 정석
> "분석할 일이 생길 수 있다" 싶으면 **네트워크 설계 단계에서** Tapping Point를 미리 만들어 두는 것이 좋다.

## 5. Burst 현상과 Micro-burst

> [!important] Burst
> 평균 대역폭은 정상이지만, **순간적으로 회선 한계를 초과**하는 트래픽 폭주 현상.

```
대역폭 ─────────────────────────────
         ↑10Gbps                    ↑10Gbps
         │                          │
         │   ┌──┐                   │
         │   │11│ ← Micro-burst     │
─────────┴───┴──┴───────────────────┴──── 시간(μs)
```

### Micro-burst

| 항목 | 내용 |
|------|------|
| **시간 단위** | 마이크로초(μs) 단위로 발생 |
| **현상** | 10Gbps 회선에 순간 11Gbps 유입 → 1Gbps 오버 |
| **결과** | 평균만 보면 정상이지만 그 순간 패킷이 **유실** |
| **고급 장비** | Micro-burst 구간도 놓치지 않고 잡아 저장 → 가격 폭등 |

## 6. DPI vs SPI — 페이로드 검사

> [!important] 패킷의 어디까지 들여다보는가?
> - **헤더만** 본다 = 송장 검사 (모두에게 허용된 영역)
> - **페이로드까지** 본다 = 박스를 열어보는 행위 (민감 영역, 법적 이슈)

### 패킷 구조와 검사 범위

```
┌──────────────────────────────────────────────────────────┐
│ L2 헤더 │ L3(IP) │ L4(TCP) │ L7(HTTP) │ Application Data │
├─────────┴────────┴─────────┼──────────┴───────────────────┤
│        Header              │         Payload              │
│   (송장 — 누구나 볼 수 있음) │   (박스 내부 — 민감)          │
└────────────────────────────┴──────────────────────────────┘
            │                          │
            │                          ├─ SPI: L7 헤더(HTTP 헤더)까지
            │                          └─ DPI: Payload 끝까지 전부
            │
            └─ 일반 라우터/방화벽: 여기까지만 봐도 동작 가능
```

### DPI / SPI 비교

| 구분 | 풀네임 | 검사 범위 |
|------|--------|-----------|
| **SPI** | **S**hallow **P**acket **I**nspection | L7 헤더(예: HTTP 헤더)까지만 |
| **DPI** | **D**eep **P**acket **I**nspection | Payload **끝까지** 전부 |

> [!tip] 비유 — 공항 수하물 검사
> SPI = 수하물 송장만 확인 / DPI = **캐리어를 열어** 속옷까지 확인.
> 본인 동의나 정당한 권한 없이 하면 **도감청** 이슈.

## 7. DPI와 법적 이슈

> [!danger] DPI는 아무 때나 할 수 있는 게 아니다
> 페이로드에는 **음성 통화 데이터, 메시지** 같은 사생활 정보가 들어 있을 수 있다.
> 한국에서는 **정보통신비밀보호법**의 보호 대상.

### 허용/금지 기준

| 주체 | 자기 회사 트래픽 검사 | ISP가 사용자 트래픽 검사 |
|------|---------------------|---------------------|
| **상황** | 회사 네트워크 → 회사 보안팀 | KT/SKT/LG → 가입자 |
| **합법성** | ✅ 문제 없음 | ❌ **월권 행위 / 법적 문제** |

### 한국의 예외 — warning.or.kr

> [!note] 국가 규정 금지 사이트 차단
> ISP 수준에서 **SPI**(L7 헤더 = HTTP Host)를 검사해서 금지 사이트 접속 시 `warning.or.kr` 로 **리다이렉트**.
> Payload 전체를 보는 DPI가 아니라 헤더 단위(SPI)이므로 운용되는 방식.

```
사용자 → 금지 사이트 요청
   │
   ▼
ISP가 SPI로 HTTP Host 헤더 검사
   │
   ├─ 정상 → Bypass
   └─ 금지 사이트 → Redirect → warning.or.kr (경찰청 안내 화면)
```

## 8. Wireshark + Npcap — 로컬 Out-of-Path 센서

> [!important] Wireshark의 정체
> Wireshark 자체는 **분석 UI**일 뿐, 패킷 캡처는 함께 설치되는 **Npcap**(또는 libpcap)이 담당.
> Npcap = **로컬 PC 수준에서 동작하는 Out-of-Path 센서**.

### 동작 구조

```
[Chrome (User mode)]
        │ 트래픽
        ▼
┌───────────────────────────┐
│   Npcap (커널 드라이버)    │
│  ┌─────────┐              │
│  │  Bypass  │ → 정상 송수신 │
│  └─────────┘              │
│       │ Copy (미러링)      │
│       ▼                    │
│   Wireshark (User mode)    │ ← 캡처된 패킷 분석/표시
└───────────────────────────┘
```

### 특징

| 항목 | 내용 |
|------|------|
| **역할** | 트래픽을 **bypass**시키면서 **사본만 전달** |
| **필터링** | 하지 않음 (방화벽이 아님) |
| **대상** | 기본은 로컬 PC, 설정으로 원격 캡처도 가능 |
| **SDK** | **Npcap Developer SDK** — C/C++로 자작 Wireshark 가능 |

> [!tip] 실무 활용
> TAP 스위치의 미러링 포트에 **Wireshark가 깔린 PC**를 연결하면 그 자체가 분석/포렌식 워크스테이션이 된다.

| **DPI** | **Payload 끝까지** 검사 — 도감청 이슈와 직결 |
| **법적 이슈** | ISP가 가입자 패킷 DPI = 월권 / 회사가 자기 트래픽 검사 = OK |
