# 스위칭과 스위치의 판단 근거

## 개요

스위칭은 네트워크 장비가 들어온 단위 데이터를 **어느 인터페이스로 보낼지 선택하는 행위**다.
스위치는 무작정 데이터를 흘려보내는 장비가 아니라, 목적지에 도달하기 위한 경로를 판단하고 선택하는 중계 지점이다.

이때 판단 근거가 어떤 계층의 정보인지에 따라 L2, L3, L4, L7 같은 스위치 분류가 생긴다.

## 한 줄 요약

> 스위칭은 단위 데이터를 전달할 인터페이스를 선택하는 일이고, 스위치는 MAC 주소 테이블이나 라우팅 테이블 같은 판단 근거를 사용해 경로를 고른다.

---

## 왜 필요한가

네트워크는 하나의 선으로만 이어진 구조가 아니다.
목적지까지 갈 수 있는 여러 경로와 중계 지점이 있고, 각 장비는 들어온 데이터를 다음 어디로 보낼지 결정해야 한다.

이 결정을 이해하면 다음 개념들이 한 덩어리로 연결된다.

- L2 스위치가 왜 MAC 주소를 보는지
- 라우터가 왜 라우팅 테이블을 보는지
- L4/L7 로드밸런서가 왜 포트, HTTP 헤더, URL 같은 정보를 보는지
- AWS VPC에서 라우팅 테이블이 왜 핵심 설정인지

---

## 핵심 개념

### 1. 스위칭 = 인터페이스 선택

> [!important] 정의
> **스위칭 = 단위 데이터를 전달할 인터페이스(경로)를 선택하는 것**

스위치는 네트워크의 교차로처럼 동작한다.
데이터가 도착하면 목적지를 확인하고, 어떤 포트 또는 인터페이스로 내보낼지 선택한다.

```
데이터 입력
   │
   ▼
[Switch]
   │  판단 근거 확인
   ├── 인터페이스 A
   ├── 인터페이스 B
   └── 인터페이스 C
```

핵심은 "전달"보다 "선택"이다.
스위치의 본질은 데이터를 다음 경로로 보내는 것이고, 그 경로 선택에는 반드시 판단 기준이 있다.

### 2. 판단 근거는 테이블이다

스위치는 내부 테이블을 기준으로 경로를 선택한다.

| 테이블 | 판단 정보 | 대표 장비 |
| --- | --- | --- |
| **MAC Address Table** | MAC 주소 | L2 스위치 |
| **Routing Table** | IP 주소 대역 | L3 스위치, 라우터 |

MAC 주소 테이블은 "이 MAC 주소는 어느 포트에 있는가"를 관리한다.
라우팅 테이블은 "이 IP 대역은 어느 인터페이스로 보내야 하는가"를 관리한다.

### 3. 계층이 달라지면 보는 정보도 달라진다

판단 근거가 OSI 7 Layer의 어느 계층 정보냐에 따라 스위치의 종류가 달라진다.

| 계층 | 주로 보는 정보 | 예시 |
| --- | --- | --- |
| L2 | MAC 주소 | L2 스위치 |
| L3 | IP 주소, IP 대역 | 라우터, L3 스위치 |
| L4 | 포트, TCP/UDP 정보 | L4 로드밸런서 |
| L7 | HTTP 헤더, URL, Host, Cookie | L7 로드밸런서, 프록시, WAF |

상위 계층 장비일수록 더 많은 의미 정보를 볼 수 있지만, 그만큼 처리 비용도 커진다.

### 4. 비용도 경로 선택의 기준이 된다

경로 선택은 단순히 거리가 짧은지를 보는 문제가 아니다.

| 비용 요소 | 의미 |
| --- | --- |
| 거리 | 물리적 또는 논리적 경로 길이 |
| 속도 | 대역폭, 처리량 |
| 소요 시간 | 실제 도달 시간, 지연 |

가까운 1Mbps 경로보다, 조금 돌아가더라도 10Gbps 경로가 더 효율적일 수 있다.
내비게이션이 거리만 보지 않고 소요 시간을 함께 고려하는 것과 같다.

## 예시

### 도로망 비유

```
출발지(A)                                    목적지(B)
  [Endpoint]                                [Endpoint]
      │                                         ▲
      ▼                                         │
   ┌──────┐     ┌──────┐     ┌──────┐     ┌──────┐
   │ ①번  │────▶│ ④번  │────▶│ ②번  │────▶│      │  ← 우회 경로
   │교차로 │     │교차로 │     │교차로 │     │      │
   └──────┘     └──────┘     └──────┘     │  B   │
      │                                    │      │
      └──────────▶┌──────┐───────────────▶│      │  ← 직진 경로
                  │ ③번  │                └──────┘
                  │교차로 │
                  └──────┘
```

- **교차로** = 스위치
- **도로** = 네트워크 경로
- **자동차** = 단위 데이터
- **내비게이션의 경로 판단 기준** = 스위치의 테이블과 비용

스위치는 교차로처럼 "다음 어디로 보낼지"를 결정한다.
경로가 여러 개라면 거리, 속도, 소요 시간 같은 비용을 고려해 더 적절한 경로를 선택한다.

### L2와 L3 비교

| 상황 | 판단 근거 | 장비 |
| --- | --- | --- |
| 같은 LAN 안에서 프레임 전달 | 목적지 MAC 주소 | L2 스위치 |
| 다른 네트워크 대역으로 패킷 전달 | 목적지 IP 대역 | 라우터, L3 스위치 |

L2에서는 MAC 주소를 보고 포트를 고른다.
L3에서는 IP 주소 대역을 보고 다음 인터페이스 또는 다음 홉을 고른다.

---

## 실무에서 주의할 점

- AWS VPC에서는 물리 L2 스위치를 직접 다루지 않지만, 라우팅 테이블은 직접 설정해야 한다.
- L2 스위칭과 L3 라우팅은 모두 넓게 보면 경로 선택이지만, 실제 판단 정보와 동작 계층은 다르다.
- L7 장비는 더 많은 정보를 보고 정교하게 판단할 수 있지만, 프로토콜 파싱과 정책 처리 때문에 더 무겁다.
- 상위 계층 스위치가 하위 계층 기능을 "대부분 포함한다"는 설명은 개념 이해용이다. 실제 제품에서는 구현 방식과 모드에 따라 다를 수 있다.

## 헷갈리기 쉬운 점

### 라우팅과 스위칭은 같은 말인가?

넓게 보면 둘 다 "경로 선택"이다.
하지만 엄밀하게는 라우팅은 보통 L3의 IP 기반 경로 선택을 가리키고, 스위칭은 더 넓거나 L2 중심의 전달 선택을 가리킬 때가 많다.

확인 필요: 사용하는 책이나 벤더 문서에 따라 "스위칭"과 "라우팅"의 범위가 다르게 설명될 수 있다.

### 라우팅 테이블은 IP를 하나씩 저장하는가?

아니다.
라우팅 테이블은 일반적으로 IP 하나하나가 아니라 `10.0.0.0/24` 같은 대역 단위로 경로를 관리한다.

### 방화벽은 스위치인가?

방화벽도 트래픽을 보고 허용, 차단, 전달 여부를 판단한다는 점에서는 경로 선택 장비처럼 이해할 수 있다.
다만 실무 장비 분류에서는 방화벽과 스위치를 같은 장비로 보지는 않는다.

확인 필요: "방화벽 = 보안 스위치"라는 표현은 학습용 비유로만 사용하고, 실제 장비 분류에서는 방화벽의 정책 검사와 보안 기능을 별도로 구분해야 한다.

---

## 면접식 설명

> 스위칭은 들어온 데이터를 어느 인터페이스로 내보낼지 선택하는 행위입니다. L2 스위치는 MAC 주소 테이블을 보고 목적지 MAC이 있는 포트로 프레임을 전달하고, 라우터나 L3 스위치는 라우팅 테이블을 보고 목적지 IP 대역에 맞는 인터페이스로 패킷을 전달합니다. 즉 스위치의 종류는 어떤 계층의 정보를 판단 근거로 삼느냐에 따라 나뉘며, 계층이 올라갈수록 URL, 헤더 같은 더 많은 의미 정보를 볼 수 있지만 처리 비용도 커집니다.
