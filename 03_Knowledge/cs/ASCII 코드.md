# 개요

**American Standard Code for Information Interchange**

컴퓨터가 문자를 숫자로 표현하기 위한 **미국 표준**이다.
컴퓨터는 0과 1(숫자)만 이해하므로, 문자를 **정수 값으로 매핑**하는 약속이 필요하다.

```
사람: "A"
컴퓨터: ???
→ "A = 65번" 이라고 약속 → 이 약속 모음이 ASCII
```

---

# 구조

**7비트 = 128개 문자**

| 범위 | 내용 | 예시 |
| --- | --- | --- |
| 0~31 | 제어 문자 | 줄바꿈(10), 탭(9) |
| 32 | 공백 | ` ` |
| 33~47 | 특수문자 | `!` `"` `#` `$` `%` |
| 48~57 | 숫자 | `0`(48) ~ `9`(57) |
| 65~90 | 영문 대문자 | `A`(65) ~ `Z`(90) |
| 97~122 | 영문 소문자 | `a`(97) ~ `z`(122) |
| 123~126 | 특수문자 | `{` `}` `~` |
| 127 | 제어 문자 | DEL (삭제) |

## 주요 문자 번호

```
'0' = 48        '9' = 57
'A' = 65        'Z' = 90
'a' = 97        'z' = 122

공백 = 32       줄바꿈 = 10
```

## 규칙

```
대문자 → 소문자: +32
'A'(65) + 32 = 'a'(97)

문자 '0' → 숫자 0: -48
'0'(48) - 48 = 0
'5'(53) - 48 = 5
```

> 이 규칙 덕분에 대소문자 변환, 문자→숫자 변환이 단순 연산으로 가능하다.

# 왜 7비트인가

ASCII가 만들어진 **1963년**, 통신과 저장 장치가 비쌌다.

```
영문 대문자 26개
영문 소문자 26개
숫자       10개
특수문자    33개
제어 문자   33개
─────────────
합계       128개 → 영어에는 충분
```

## 왜 1바이트(8비트)로 저장하는가

ASCII는 7비트지만 컴퓨터는 **8비트(1byte) 단위**로 처리한다.

```
[0][7bit ASCII]

'A' = 0 1000001 (8bit, 최상위 비트는 0)
```

> 남는 1비트는 0으로 채우거나, 후에 Extended ASCII에서 활용되었다.

# 제어 문자

화면에 보이지 않지만 **동작을 지시**하는 문자다.

| 번호 | 이름 | 의미 |
| --- | --- | --- |
| 0 | NULL | 없음 |
| 9 | TAB | 탭 |
| 10 | LF | 줄바꿈 (Linux/Mac) |
| 13 | CR | 캐리지 리턴 |
| 27 | ESC | 이스케이프 |
| 127 | DEL | 삭제 |

> 타자기 시대의 유산이다. CR은 "커서를 줄 맨 앞으로", LF는 "종이를 한 줄 올려라"라는 의미. Windows는 CR+LF를 함께 사용한다.

# 이후 발전

```
ASCII (7bit, 128자) — 영문만
    ↓
Extended ASCII (8bit, 256자) — 유럽 문자 일부 추가, 표준 미통일
    ↓
각국 독자 인코딩 (EUC-KR, Shift_JIS) — 서로 호환 안됨
    ↓
Unicode + UTF-8 — 전 세계 문자 통합
```

## Extended ASCII

8비트 전체를 사용하면 **256개(2^8)** 표현이 가능하다.

- é, ñ 같은 유럽 문자 추가
- 하지만 **표준이 통일되지 않아** 시스템마다 다른 문자가 표시되는 문제 발생

## 개발자 관점

### 네트워크/프로토콜

HTTP 헤더, SMTP, TCP text protocol 등 대부분 **ASCII 기반**이다.

### UTF-8과의 관계

ASCII는 [[Unicode]]의 인코딩 방식인 UTF-8의 **부분집합**이다.

- ASCII 영역(0~127)은 UTF-8에서도 **동일한 1바이트**로 표현
- ASCII 파일을 UTF-8로 읽어도 그대로 동작한다 (하위 호환성)
