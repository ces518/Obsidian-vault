# 개요

**전 세계 모든 문자에 고유 번호(코드 포인트)를 부여한 국제 표준**이다.

각 문자에 번호를 매기는 것이 전부이며, 저장 방식은 별도의 인코딩(UTF-8 등)이 담당한다.

```
'A' → U+0041
'가' → U+AC00
'日' → U+65E5
'😀' → U+1F600
```

현재 **15만자 이상** 등록 (한글, 한자, 이모지, 고대 문자 등)

---

# 왜 필요했는가

```
ASCII 시대:
  미국 → ASCII
  한국 → EUC-KR
  일본 → Shift_JIS
  중국 → GB2312

문제: 같은 숫자가 나라마다 다른 문자를 의미
  → 한국 파일을 일본에서 열면 글자 깨짐
```

> 하나의 표준으로 **모든 문자를 통합**하자 → Unicode

# 유니코드 ≠ 인코딩

| | 유니코드 | 인코딩 (UTF-8 등) |
| --- | --- | --- |
| 종류 | 문자 집합 (Character Set) | 인코딩 (Encoding) |
| 역할 | 문자 → **번호** 부여 | 번호 → **바이트** 변환 |
| 비유 | 전화번호부 (문자 목록) | 전화를 거는 방식 (저장/전송) |

> 유니코드는 "**무엇**을 표현할지", 인코딩은 "**어떻게** 저장할지"

# 대표 인코딩 방식

## UTF-8 (가장 널리 사용)

```
'A'  → 1바이트  (0x41)
'가' → 3바이트  (0xEA 0xB0 0x80)
'😀' → 4바이트
```

| 특징 | 설명 |
| --- | --- |
| 가변 길이 | 1~4바이트 |
| [[ASCII 코드]] 호환 | 영문은 ASCII와 동일한 1바이트 |
| 웹 표준 | HTML, JSON, API 대부분 UTF-8 |

> ASCII 파일을 UTF-8로 읽어도 그대로 동작한다 (하위 호환성). 가변 길이 처리 원리는 [[UTF-8 가변 길이 처리 원리]] 참고.

## UTF-16

```
'A'  → 2바이트
'가' → 2바이트
'😀' → 4바이트 (서로게이트 페어)
```

| 특징 | 설명 |
| --- | --- |
| 가변 길이 | 2 또는 4바이트 |
| 사용처 | Java, JavaScript, Windows 내부 |

## UTF-32

```
'A'  → 4바이트
'가' → 4바이트
'😀' → 4바이트
```

| 특징 | 설명 |
| --- | --- |
| 고정 길이 | 항상 4바이트 |
| 장점 | 인덱싱이 쉬움 (n번째 문자 = n×4 위치) |
| 단점 | 메모리 낭비가 큼 |

# 인코딩별 비교

```
'A' 저장 시:
  UTF-8  → 1바이트  ← 효율적
  UTF-16 → 2바이트
  UTF-32 → 4바이트

'가' 저장 시:
  UTF-8  → 3바이트
  UTF-16 → 2바이트  ← 효율적
  UTF-32 → 4바이트
```

> 영문 중심이면 UTF-8이 효율적, 한중일 중심이면 UTF-16이 효율적

# 문자 인코딩 발전 흐름

```
ASCII (7bit, 128자) — 영문만
    ↓
Extended ASCII (8bit, 256자) — 유럽 문자 일부, 표준 미통일
    ↓
각국 독자 인코딩 (EUC-KR, Shift_JIS) — 서로 호환 안됨
    ↓
Unicode (전 세계 문자에 번호 부여) — "무엇을" 정의
    ↓
UTF-8 / UTF-16 / UTF-32 — "어떻게" 저장할지 결정
```

> Unicode = 전 세계 문자의 **전화번호부**, UTF-8 = 그 번호를 **바이트로 저장하는 방식**
