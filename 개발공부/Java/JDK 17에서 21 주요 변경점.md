# JDK 17 → 21 주요 변경점

JDK 17과 21은 모두 LTS(Long-Term Support) 버전이며, 그 사이 JDK 18/19/20을 거치면서 다수의 기능이 Preview → Finalized 되었다.

---

## 문법 변경 (Language Features)

### Pattern Matching for switch (JEP 441)

JDK 17에서는 Preview였으나 **21에서 정식 확정** 되었다.

```java
// Before (JDK 17)
if (obj instanceof String s) {
    System.out.println(s.length());
} else if (obj instanceof Integer i) {
    System.out.println(i.intValue());
} else {
    System.out.println("unknown");
}

// After (JDK 21)
switch (obj) {
    case String s  -> System.out.println(s.length());
    case Integer i -> System.out.println(i.intValue());
    case null      -> System.out.println("null!");     // null 분기 가능
    default        -> System.out.println("unknown");
}
```

**Guarded Pattern** (`when` 절) 지원:

```java
switch (obj) {
    case String s when s.length() > 5 -> System.out.println("long string");
    case String s                      -> System.out.println("short string");
    default                            -> System.out.println("not a string");
}
```

### Record Patterns (JEP 440)

Record의 컴포넌트를 **패턴 매칭으로 분해(destructuring)** 할 수 있다.

```java
record Point(int x, int y) {}
record Line(Point start, Point end) {}

// 중첩 분해까지 가능
if (obj instanceof Line(Point(var x1, var y1), Point(var x2, var y2))) {
    System.out.println("Line from (%d,%d) to (%d,%d)".formatted(x1, y1, x2, y2));
}

// switch와 결합
switch (shape) {
    case Point(var x, var y)           -> System.out.printf("Point(%d,%d)%n", x, y);
    case Line(Point p1, Point p2)      -> System.out.printf("Line(%s->%s)%n", p1, p2);
    default                            -> System.out.println("unknown shape");
}
```

### Unnamed Patterns & Variables (JEP 443 — Preview)

사용하지 않는 변수를 `_` 로 표현한다.

```java
// 사용하지 않는 변수
try {
    // ...
} catch (Exception _) {   // 변수명 불필요
    System.out.println("error occurred");
}

// Record Pattern에서 일부 컴포넌트 무시
if (obj instanceof Point(var x, _)) {
    System.out.println("x = " + x);  // y는 불필요
}

// enhanced for-loop
for (var _ : list) {
    count++;  // 요소 자체는 불필요, 횟수만 필요
}
```

### Unnamed Classes & Instance Main Methods (JEP 445 — Preview)

진입점을 간소화하여 초보자 친화적 코드 작성이 가능하다.

```java
// Before
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

// After (JDK 21 Preview)
void main() {
    System.out.println("Hello, World!");
}
```

## 핵심 API / 런타임 변경

### Virtual Threads (JEP 444)

JDK 21 최대의 변경점. **경량 스레드**로 대규모 동시성 처리가 가능하다.

```java
// 방법 1: 직접 생성
Thread vt = Thread.ofVirtual().name("my-vt").start(() -> {
    System.out.println("Running on: " + Thread.currentThread());
});

// 방법 2: ExecutorService
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    IntStream.range(0, 100_000).forEach(i ->
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1));
            return i;
        })
    );
}
// 10만 개의 동시 태스크도 OS 스레드 수십 개로 처리
```

**핵심 특징:**

- Platform Thread 대비 메모리 약 1/1000 (수 KB vs 수 MB)
- `synchronized` 블록 내에서 blocking 시 carrier thread가 pinning됨 → `ReentrantLock` 권장
- Spring Boot 3.2+ 에서 `spring.threads.virtual.enabled=true` 로 간단 적용 가능

### Sequenced Collections (JEP 431)

순서가 있는 컬렉션에 **공통 인터페이스**가 추가되었다.

```java
// 새로 추가된 인터페이스 계층
// SequencedCollection<E>  extends Collection<E>
// SequencedSet<E>         extends SequencedCollection<E>, Set<E>
// SequencedMap<K,V>       extends Map<K,V>
```

```java
List<String> list = List.of("a", "b", "c");
list.getFirst();     // "a"    (기존: list.get(0))
list.getLast();      // "c"    (기존: list.get(list.size()-1))
list.reversed();     // ["c", "b", "a"] — reversed view

LinkedHashSet<String> set = new LinkedHashSet<>(List.of("x", "y", "z"));
set.getFirst();      // "x"
set.getLast();        // "z"

LinkedHashMap<String, Integer> map = new LinkedHashMap<>();
map.firstEntry();    // 첫 번째 엔트리
map.lastEntry();     // 마지막 엔트리
map.sequencedKeySet().reversed();  // 역순 키셋 view
```

### Structured Concurrency (JEP 453 — Preview)

여러 동시 태스크를 **하나의 단위로 관리**한다.

```java
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Subtask<String> user  = scope.fork(() -> findUser(userId));
    Subtask<Order>  order = scope.fork(() -> findOrder(orderId));

    scope.join();            // 둘 다 완료 대기
    scope.throwIfFailed();   // 하나라도 실패 시 예외

    return new Response(user.get(), order.get());
}
// scope 종료 시 미완료 subtask 자동 취소
```

### Scoped Values (JEP 446 — Preview)

`ThreadLocal`의 대안으로, Virtual Thread 환경에 최적화되어 있다.

```java
private static final ScopedValue<User> CURRENT_USER = ScopedValue.newInstance();

// 값 바인딩 (불변, 스코프 벗어나면 자동 해제)
ScopedValue.runWhere(CURRENT_USER, authenticatedUser, () -> {
    handleRequest();  // 이 안에서 CURRENT_USER.get() 가능
});
```

**ThreadLocal 대비 장점:**

- 불변(immutable) → 실수로 다른 곳에서 덮어쓸 수 없음
- 스코프 기반 → GC 친화적, 메모리 누수 방지
- Virtual Thread에서 상속 비용 없음

## 성능 / GC 변경

### Generational ZGC (JEP 439)

ZGC에 **세대별(Generational) 수집**이 추가되었다.

```bash
# JDK 21에서 활성화
java -XX:+UseZGC -XX:+ZGenerational ...

# 기존 non-generational ZGC도 계속 사용 가능
java -XX:+UseZGC ...
```

- Young/Old Generation 분리로 대부분의 워크로드에서 처리량 향상
- 일시 정지 시간은 기존과 동일하게 sub-millisecond 유지

## 마이그레이션 시 주의사항

### synchronized → ReentrantLock

Virtual Thread를 사용한다면 `synchronized` 블록에서 blocking I/O 시 **pinning 발생**. 성능 병목이 될 수 있으므로 `ReentrantLock` 으로 전환 권장.

### ThreadLocal 점검

Virtual Thread 환경에서 ThreadLocal은 **메모리 누수 위험 증가**. `ScopedValue` 전환 검토.

### finalize() 제거

Deprecated for Removal 상태이므로 `Cleaner` 또는 **try-with-resources**로 대체.

### 기본 Charset 변경

JDK 18부터 UTF-8이 기본값. 기존에 플랫폼 인코딩(예: EUC-KR)에 의존하던 코드는 **깨질 수 있음**.

### Reflection 접근 제한 강화

`--illegal-access` 옵션이 JDK 17에서 이미 제거됨. 내부 API 접근 시 `--add-opens` 명시 필요.

### Security Manager 비권장

JDK 17부터 Deprecated. 21에서도 유지되지만 **향후 제거 예정**.
