# 개요

UTF-8은 [[Unicode]] 코드 포인트를 **1~4바이트 가변 길이**로 저장하는 인코딩이다. **첫 바이트의 비트 패턴**으로 해당 문자가 몇 바이트인지 알려준다.

---

# 인코딩 규칙

| 바이트 수 | 첫 바이트 패턴 | 이후 바이트 패턴 | 유니코드 범위 |
| --- | --- | --- | --- |
| 1바이트 | `0xxxxxxx` | - | U+0000 ~ U+007F |
| 2바이트 | `110xxxxx` | `10xxxxxx` | U+0080 ~ U+07FF |
| 3바이트 | `1110xxxx` | `10xxxxxx` ×2 | U+0800 ~ U+FFFF |
| 4바이트 | `11110xxx` | `10xxxxxx` ×3 | U+10000 ~ U+10FFFF |

> 첫 바이트 앞의 `1`의 개수 = 총 바이트 수. 이후 바이트는 항상 `10`으로 시작한다.

---

# 인코딩 예시

## 'A' → 1바이트

```
유니코드: U+0041 = 1000001 (7비트)

0 1000001
↑
0으로 시작 → "1바이트다"

결과: 0x41 (1바이트)
```

## '가' → 3바이트

```
유니코드: U+AC00 = 1010 110000 000000 (16비트)

1110 1010  10 110000  10 000000
↑↑↑↑       ↑↑         ↑↑
1이 3개    이후 바이트  이후 바이트
→ "3바이트다"  → "10 = 이어지는 바이트"

결과: 0xEA 0xB0 0x80 (3바이트)
```

## '😀' → 4바이트

```
유니코드: U+1F600 = 000 011111 011000 000000 (21비트)

11110 000  10 011111  10 011000  10 000000
↑↑↑↑↑      ↑↑         ↑↑         ↑↑
1이 4개   이어짐     이어짐     이어짐
→ "4바이트다"

결과: 0xF0 0x9F 0x98 0x80 (4바이트)
```

# 디코딩 과정

```
첫 바이트를 본다
    │
    ├── 0으로 시작     → 1바이트, 바로 읽기
    ├── 110으로 시작   → 2바이트, 다음 1개 더 읽기
    ├── 1110으로 시작  → 3바이트, 다음 2개 더 읽기
    └── 11110으로 시작 → 4바이트, 다음 3개 더 읽기

이후 바이트는 항상 10으로 시작 → "나는 이어지는 바이트"
```

# 설계의 장점

## 1. [[ASCII 코드]] 완벽 호환

```
ASCII 'A' = 0x41 = 0 1000001
UTF-8 'A' = 0x41 = 0 1000001  ← 동일
```

ASCII 범위(0~127)는 UTF-8에서도 동일한 1바이트이므로, 기존 ASCII 시스템과 하위 호환된다.

## 2. 중간부터 읽어도 위치 파악 가능

```
... 10xxxxxx 10xxxxxx 1110xxxx 10xxxxxx 10xxxxxx ...
    ↑                 ↑
    "이어지는 바이트"   "여기가 시작점"
```

`10`으로 시작하면 중간 바이트이고, 그 외 패턴이면 문자의 시작점이다. 바이트 스트림의 어느 위치에서든 **문자 경계를 찾을 수 있다.**

## 3. 바이트 단위 정렬 = 유니코드 순서

```
'A' (0x41) < '가' (0xEA...) < '😀' (0xF0...)
```

바이트 값을 단순 비교하면 유니코드 코드 포인트 순서와 일치한다.

---

# 정리

> UTF-8은 **첫 바이트의 비트 패턴**으로 길이를 알려주고, 이후 바이트는 `10`으로 시작하여 구분한다. 이 덕분에 ASCII 호환 + 어디서든 문자 경계 파악이 가능하다.
