## 개요

**VPN(Virtual Private Network)** 의 핵심 동작 원리인 **터널링(Tunneling) + 암호화(Encryption) + 캡슐화(Encapsulation)** 의 조합을 다룬다.
또한 VPN을 통해 **해외 IP로 위장**해 지역 차단을 우회하는 원리와 한계도 정리한다.

---

## 1. VPN의 본질 — 세 가지 기술의 조합

> [!important] VPN ≠ 단순 헤더 조작
> VPN은 단순히 헤더를 바꾸는 것이 아니라, **캡슐화 + 암호화 + 터널링**의 결합 기술이다.

| 기술 | 역할 | 비유 |
|------|------|------|
| **Encapsulation (캡슐화)** | 원본 패킷 전체를 새 패킷의 페이로드로 감싸기 | 편지를 봉투에 넣고, 그 봉투를 더 큰 봉투에 넣기 |
| **Encryption (암호화)** | 내부 패킷(헤더+데이터)을 암호화 | 봉투 내용물을 잠금 처리 |
| **Tunneling (터널링)** | 새 외부 헤더로 VPN 서버 주소만 노출 | 외부에서 보면 "VPN 서버랑 통신 중"으로만 보임 |

## 2. VPN 패킷의 구조

![[Pasted image 20260510193909.png]]

### 단계별 변환

```
[① 원본 패킷]
┌─────────────┬────────────────────┐
│  원본 헤더    │   데이터 (페이로드)   │
│ 출발지/목적지 │   실제 전송 내용      │
└─────────────┴────────────────────┘
            │
            │ 암호화
            ▼
[② 암호화된 페이로드]
┌──────────────────────────────────┐
│ 🔒 암호화된 원본 패킷 전체           │
│    (헤더 + 데이터 모두 암호화됨)     │
└──────────────────────────────────┘
            │
            │ 캡슐화
            ▼
[③ VPN 패킷 (실제 전송되는 모습)]
┌──────────┬───────────────────────┐
│ 새 외부   │ 🔒 암호화된 페이로드     │
│ 헤더      │   (원본 헤더 + 원본 데이터)│
│VPN 서버 IP│                       │
└──────────┴───────────────────────┘
```

> [!note] 외부 관찰자가 볼 수 있는 것
> ISP, 공격자 등 중간 관찰자는 **"VPN 서버로 가는 패킷"** 이라는 사실만 알 수 있을 뿐,
> 실제 목적지와 내용은 암호화되어 알 수 없음.

## 3. 주요 VPN 프로토콜

| 프로토콜 | 계층/특징 |
|---------|----------|
| **IPsec** | IP 계층(L3)에서 캡슐화 — 표준 VPN 프로토콜 |
| **OpenVPN** | SSL/TLS 기반 — 유연성 높음, 오픈소스 |
| **WireGuard** | 최신 경량 프로토콜 — 빠르고 단순한 구조 |
| **L2TP** | L2 터널링 — 보통 IPsec과 결합해서 사용 |

각 프로토콜은 **캡슐화 방식과 암호화 알고리즘**이 다름.

## 4. 해외 IP로 보이는 원리 — 대리 접속(Proxy)

> [!important] 핵심 메커니즘
> VPN 서버가 사용자 대신 목적지에 **NAT 방식으로 대리 접속**한다.

![[Pasted image 20260510193930.png]]

### 단계별 흐름

```
[요청 경로: User → Site]

사용자 (한국)             VPN 서버 (미국)            해외 사이트
실제 IP:                   IP:                       (예: netflix.com)
211.xx.xx.xx              104.xx.xx.55                  
   │                          │                          │
   │ ① 암호화 터널              │                          │
   │ ─────────────────────────▶│                          │
   │                          │ ② IP 치환 후 새 요청       │
   │                          │   Src: 104.xx.xx.55      │
   │                          │ ─────────────────────────▶│
   │                          │                          │
   │                          │                          │ ③ 사이트 인식:
   │                          │                          │   "미국에서 접속한 사용자"
```

```
[응답 경로: Site → User]

해외 사이트                VPN 서버                  사용자
   │                          │                          │
   │ ④ 응답 (Dst:104.xx.xx.55) │                          │
   │ ─────────────────────────▶│                          │
   │                          │ ⑤ 매핑 테이블 조회         │
   │                          │   "이 응답은 사용자 A의 것" │
   │                          │ ⑥ 암호화 후 전달           │
   │                          │ ─────────────────────────▶│
```

### 핵심 메커니즘 정리

| 단계 | 동작 |
|------|------|
| **1단계** | 사용자 → VPN 서버 (암호화 터널) |
| **2단계** | VPN 서버가 자신의 IP로 **출발지를 치환**하여 목적지 접속 (NAT 유사) |
| **3단계** | 목적지는 **VPN 서버 IP만** 보이므로 "미국 접속자"로 판단 |
| **4단계** | 응답은 VPN 서버로 → 매핑 테이블 조회 후 사용자에게 암호화 전달 |

## 5. 왜 IP 위장이 가능한가?

> [!note] IP 기반 위치 판단의 원리
> 인터넷의 위치 추정은 **WHOIS, GeoIP DB**(IP 주소가 등록된 지역 정보)에 기반한다.
> VPN은 이 판단의 **입력값(출발지 IP) 자체를 바꿔버리기** 때문에 우회가 가능.

### 우회되는 시나리오

- IP 기반 **지역 차단(Geo-blocking)**
- 국가별 콘텐츠 제한 (Netflix, YouTube 지역 라이선스 등)
- ISP 단의 검열/차단

### 우회되지 않는 시나리오

사이트가 **추가 검증 수단**을 사용하면 우회 불가:

- GPS 위치 정보
- 결제 카드 발급 국가
- 휴대폰 번호 국가 코드
- 계정 등록 국가

## 6. VPN의 한계와 차단

> [!caution] VPN ≠ 완벽한 익명성
> IP만 바꾼다고 해서 모든 위치 정보가 숨겨지는 것은 아니다.

### 알려진 한계

| 차단/누출 방법 | 설명 |
|--------------|------|
| **VPN IP 블랙리스트** | Netflix, Disney+ 등이 알려진 VPN 서버 IP 대역을 차단 |
| **DNS 누출** | DNS 질의가 ISP의 DNS로 새어나가면 실제 위치 노출 |
| **WebRTC 누출** | 브라우저의 WebRTC가 실제 IP를 노출시킬 수 있음 |
| **브라우저 핑거프린팅** | 언어, 시간대, 폰트 등 메타데이터로 위치 추정 |
| **HTTPS의 SNI** | 일부 환경에서 접속 도메인이 평문 노출 |

### 권장 보완책

- **DNS 누출 방지**: VPN의 자체 DNS 사용
- **Kill Switch**: VPN 연결 끊기면 인터넷 차단
- **Multi-hop VPN**: 여러 VPN 서버를 거쳐 추적 어려움

## 핵심 요약

> [!summary]
> 1. VPN의 본질 = **캡슐화 + 암호화 + 터널링**의 조합
> 2. **캡슐화**: 원본 패킷(헤더+데이터)을 새 패킷의 페이로드로 감쌈
> 3. **암호화**: 원본 패킷 전체를 암호화 → 중간 가로채도 내용 불가시
> 4. **터널링**: 새 외부 헤더에는 VPN 서버 IP만 적힘 → 외부엔 "VPN 통신"으로만 보임
> 5. 주요 프로토콜: **IPsec, OpenVPN, WireGuard, L2TP**
> 6. 해외 IP 위장 원리: VPN 서버가 **자신의 IP로 출발지를 치환**해 대리 접속 (NAT 유사)
> 7. 사이트는 **VPN 서버 IP만** 보므로 "미국 접속자"로 판단 → 지역 차단 우회
> 8. 위치 판단은 **WHOIS/GeoIP DB**에 의존 — 입력값(IP)을 바꾸면 우회 가능
> 9. 한계: **VPN IP 블랙리스트**, DNS/WebRTC 누출, 브라우저 핑거프린팅
> 10. 추가 검증(GPS, 결제카드 국가 등)을 적용하면 IP 위장만으로는 우회 불가
