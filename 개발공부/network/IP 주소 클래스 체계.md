## 개요

L3(네트워크 계층)의 핵심인 **IP 주소**의 구조와 **클래스(Classful) 체계**를 다룬다.
IP 주소가 어떻게 네트워크와 호스트를 구분하는지, 각 클래스의 특징과 한계를 정리한다.

---

## 1. IP 주소란?

> [!important] 정의
> **IP 주소** = 인터넷(L3)에서 호스트를 식별하기 위한 **32비트 논리 주소** (IPv4 기준)

| 항목 | 내용 |
|------|------|
| **계층** | L3 (네트워크 계층) |
| **크기** | 32비트 (4바이트) |
| **성격** | Logical(논리적) — 소프트웨어적으로 부여, **변경 가능** |
| **표기법** | Dotted Decimal (점으로 구분된 10진수) |

### IP 주소 표기법

```
  11000000.10101000.00000001.00000001   ← 2진수 (32비트)
     │         │        │       │
  192    .   168   .    1   .    1      ← 10진수 (Dotted Decimal)
```

- 32비트를 **8비트(1옥텟)씩 4개**로 나누어 10진수로 표기
- 각 옥텟의 범위: **0 ~ 255** (8비트 = 2^8 = 256가지)

### MAC 주소와의 비교

| 구분 | MAC 주소 | IP 주소 |
|------|---------|---------|
| **계층** | L2 | L3 |
| **크기** | 48비트 | 32비트 |
| **성격** | Physical (하드웨어에 부여) | Logical (소프트웨어로 부여) |
| **변경** | Virtual MAC으로 변경 가능 | 설정으로 자유롭게 변경 |
| **범위** | LAN 내 | 인터넷 전체 |

## 2. IP 주소의 구조 — Network ID + Host ID

> [!important] 핵심 구조
> IP 주소 = **Network ID** + **Host ID**

```
┌─────────────────────────────┬─────────────────────────────┐
│        Network ID           │          Host ID            │
│   (어느 네트워크인가?)        │   (그 안의 어느 호스트인가?)   │
└─────────────────────────────┴─────────────────────────────┘
                        32비트
```

- **Network ID**: 어떤 네트워크(대역)에 속하는지 식별
- **Host ID**: 해당 네트워크 내에서 개별 호스트를 식별
- 비유: 네트워크 = **동네**, 호스트 = **집 번호**

> 같은 네트워크에 속한 호스트들은 **Network ID가 동일**하다.

## 3. 클래스(Classful) 체계

IP 주소의 **첫 번째 옥텟(첫 비트 패턴)**에 따라 클래스를 구분한다.

### 클래스별 분류

| 클래스 | 첫 비트 패턴 | 첫 옥텟 범위 | Network ID | Host ID | 용도 |
|--------|------------|-------------|------------|---------|------|
| **A** | `0xxxxxxx` | **1 ~ 126** | 8비트 (1옥텟) | 24비트 (3옥텟) | 대규모 네트워크 |
| **B** | `10xxxxxx` | **128 ~ 191** | 16비트 (2옥텟) | 16비트 (2옥텟) | 중규모 네트워크 |
| **C** | `110xxxxx` | **192 ~ 223** | 24비트 (3옥텟) | 8비트 (1옥텟) | 소규모 네트워크 |
| **D** | `1110xxxx` | **224 ~ 239** | — | — | 멀티캐스트 |
| **E** | `1111xxxx` | **240 ~ 255** | — | — | 예약 (실험용) |

> [!note] 실무에서 사용하는 클래스: A, B, C
> D(멀티캐스트)와 E(예약)는 일반 호스트에 할당하지 않는다.

### 클래스별 구조 시각화

```
Class A:  N  .  H  .  H  .  H     ← 네트워크 적고, 호스트 많음
          ├──┤  ├──────────────┤
          8bit      24bit

Class B:  N  .  N  .  H  .  H     ← 균형
          ├────────┤  ├────────┤
            16bit       16bit

Class C:  N  .  N  .  N  .  H     ← 네트워크 많고, 호스트 적음
          ├──────────────┤  ├──┤
               24bit       8bit
```

## 4. 클래스별 네트워크 수와 호스트 수

| 클래스 | 네트워크 수 | 네트워크당 호스트 수 | 특징 |
|--------|-----------|-------------------|------|
| **A** | 126개 | 약 **1,677만**개 (2^24 - 2) | 소수의 거대 네트워크 |
| **B** | 약 16,384개 | 약 **65,534**개 (2^16 - 2) | 중간 규모 |
| **C** | 약 2,097,152개 | **254**개 (2^8 - 2) | 다수의 소규모 네트워크 |

> [!note] 호스트 수에서 -2 하는 이유
> - **Network Address** (Host ID 전부 0): 네트워크 자체를 지칭
> - **Broadcast Address** (Host ID 전부 1): 해당 네트워크 전체에 방송
> - 이 두 주소는 호스트에 할당할 수 없으므로 제외

---

## 5. 특수 주소

| 주소 | 설명 |
|------|------|
| **0.0.0.0** | 자기 자신 (미지정, 기본 경로) |
| **127.0.0.1** | Loopback (자기 자신에게 보내는 테스트 주소) |
| **127.x.x.x** | Loopback 대역 (Class A 중 127은 예약) |
| **255.255.255.255** | 제한된 Broadcast (로컬 네트워크 전체) |

> [!tip] 첫 옥텟이 127인 이유
> Class A의 범위는 1~126이고, **127은 Loopback용으로 예약**되어 있다.
> 따라서 Class A 네트워크는 실제로 **126개**만 사용 가능.

## 6. 사설 IP 주소 (Private IP)

인터넷에서 사용하지 않고 **LAN 내부에서만 사용**하는 예약된 주소 대역.

| 클래스 | 사설 IP 대역 | 범위 |
|--------|-------------|------|
| **A** | `10.0.0.0/8` | 10.0.0.0 ~ 10.255.255.255 |
| **B** | `172.16.0.0/12` | 172.16.0.0 ~ 172.31.255.255 |
| **C** | `192.168.0.0/16` | 192.168.0.0 ~ 192.168.255.255 |

> [!example] 우리 집 공유기
> 공유기 내부에서 사용하는 `192.168.0.x` 또는 `192.168.1.x`가 대표적인 **Class C 사설 IP** 대역이다.

- 사설 IP는 인터넷에서 라우팅되지 않음 → 외부 통신 시 **NAT(Network Address Translation)**를 통해 공인 IP로 변환
- **AWS VPC** 생성 시에도 사설 IP 대역을 CIDR로 지정 (예: `10.0.0.0/16`)

## 7. Classful 체계의 한계와 CIDR

### 한계

- Class A는 호스트 1,677만 개 → **IP 낭비** (그만큼 쓸 조직이 거의 없음)
- Class C는 호스트 254개 → **부족** (중소규모 조직에게 너무 적음)
- 클래스 단위로만 나누다 보니 **유연성 부족**

### CIDR (Classless Inter-Domain Routing)

> [!important] CIDR = 클래스 구분 없이, 비트 수로 네트워크 범위를 자유롭게 지정

```
192.168.1.0 / 24
├──────────┤  ├┤
  IP 주소      서브넷 마스크 (앞에서부터 24비트가 Network ID)
```

| 표기 | Network ID | Host ID | 호스트 수 |
|------|-----------|---------|----------|
| `/24` | 24비트 | 8비트 | 254개 |
| `/16` | 16비트 | 16비트 | 65,534개 |
| `/28` | 28비트 | 4비트 | 14개 |

- CIDR 덕분에 **필요한 만큼만** 네트워크를 쪼개서 사용 가능
- 현재는 Classful 체계 대신 **CIDR이 표준**

> [!tip] AWS에서의 CIDR
> - VPC 생성: `10.0.0.0/16` (65,536개 IP)
> - Subnet 생성: `10.0.1.0/24` (256개 IP, 실사용 251개)
> - AWS는 서브넷당 **5개 IP를 예약** (네트워크, 라우터, DNS, 예약, Broadcast)

## 핵심 요약

> [!summary]
> 1. **IP 주소** = 32비트 논리 주소, L3에서 호스트를 식별 (Logical = 변경 가능)
> 2. IP 주소 = **Network ID** (어느 네트워크?) + **Host ID** (어느 호스트?)
> 3. **Class A** (1~126): 네트워크 적고 호스트 많음 / **B** (128~191): 균형 / **C** (192~223): 네트워크 많고 호스트 적음
> 4. 호스트 수 계산 시 **-2** (Network Address + Broadcast Address 제외)
> 5. **127.x.x.x** = Loopback 예약 / **0.0.0.0** = 미지정 / **255.255.255.255** = Broadcast
> 6. **사설 IP**: 10.x.x.x / 172.16~31.x.x / 192.168.x.x → LAN 전용, NAT로 외부 통신
> 7. Classful 체계는 **IP 낭비** 문제 → **CIDR**로 대체 (비트 수로 자유롭게 분할)
> 8. AWS VPC/Subnet은 **CIDR 표기법**으로 네트워크 범위를 지정
